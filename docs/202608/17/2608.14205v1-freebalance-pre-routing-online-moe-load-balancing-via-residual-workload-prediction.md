## 摘要
负载不均是混合专家（MoE）模型分布式推理中专家并行效率的主要瓶颈。由于路由分布倾斜，负载最高的秩会阻塞全局执行，直接增加延迟。虽然离线专家放置可以缓解持续的不均衡，但实际的多任务服务负载表现出依赖层和批次的路由动态，使得在线负载均衡不可或缺。现有方法依赖每个MoE路由器之后收集的路由统计信息，要求专家权重加载或迁移只能在路由决策可用之后开始，因此将迁移开销置于推理关键路径上。在这项工作中，我们观察到，如果能够提前准确预测路由分布，在线均衡可以在目标路由（例如注意力）之前的计算阶段大部分重叠。因此，我们提出FreeBalance，一种无损的在线负载均衡框架，通过残差工作负载预测将专家迁移与前面的计算阶段重叠。FreeBalance利用残差网络内隐藏表示的跨层相似性来构建轻量级工作负载预测器。这使得在路由决策可用之前就能进行主动的专家迁移规划，在权重传输和计算密集型路由前阶段之间创造大量重叠。此外，一个成本模型限制交换次数，以在可用窗口内完全隐藏同步开销。跨模型和数据集的实验表明，FreeBalance将最大与平均秩负载比降低了32.8%，端到端预填充延迟降低了13.1%。具体来说，我们的方法隐藏了每层平均5.1个专家的均衡开销，否则这些开销将占关键路径延迟的约8.5%。

## Abstract
Load imbalance poses a major bottleneck to the efficiency of expert parallelism in distributed inference of Mixture-of-Experts (MoE) models. The most heavily loaded rank stalls global execution due to skewed routing distributions, directly increasing latency. While offline expert placement can alleviate persistent imbalance, practical multi-task serving workloads exhibit layer- and batch-dependent routing dynamics, making online load balancing indispensable. Existing approaches rely on routing statistics collected after each MoE router, requiring expert weight load or migration to begin only after routing decisions are available, consequently placing migration overhead on the inference critical path. In this work, we observe that online balancing can instead be largely overlapped with computation before target routing (e.g., attention), if routing distributions can be predicted accurately in advance. Therefore, we propose FreeBalance, a lossless online load-balancing framework that overlaps expert migration with preceding computation stages via residual workload prediction. FreeBalance leverages cross-layer similarities in hidden representations within the residual network to build a lightweight workload predictor. This enables proactive expert migration planning before routing decisions are available, creating substantial overlap between weight transfer and computation-heavy pre-routing stages. Furthermore, a cost model constrains the number of swaps to fully hide the synchronization overhead within the available window. Experiments across models and datasets show that FreeBalance reduces the max-to-mean rank load ratio by 32.8% and end-to-end prefill latency by 13.1%. Specifically, our method hides balancing overhead of an average of 5.1 experts per layer, which would otherwise account for about 8.5% of the critical-path latency.

# FreeBalance：基于残差工作负载预测的路由前在线MoE负载均衡

## 1. 核心问题与整体含义（研究动机和背景）

- **问题背景**：MoE（混合专家）模型已成为现代大语言模型的主流架构，其通过稀疏路由激活少量专家，在提升参数容量的同时控制单 token 计算成本。在分布式推理中，专家并行（EP）被广泛采用，但**路由分布偏斜会导致不同设备（rank）上的负载严重不均衡**，最重的 rank 成为同步瓶颈，迫使轻载设备空闲等待，直接增加端到端延迟。
- **现有方法的不足**：
  - **离线负载均衡**（如 DeepSeek EPLB）基于历史路由统计固定专家放置，在多任务服务场景下，不同任务类型的路由分布差异显著，静态映射无法快速适应动态变化。
  - **在线负载均衡**依赖路由完成后的统计信息，必须先在当前层路由结束后才能获得分布，然后才能规划专家迁移。这一过程被限制在“路由完成”到“专家执行”之间的狭窄区间，而该区间位于推理关键路径上，迁移开销会直接增加延迟。
- **FreeBalance 的核心洞察**：如果能在路由执行前准确预测即将到来的专家负载，就可以提前规划专家迁移，并将其与路由前的计算阶段（主要是注意力计算）重叠，从而**将迁移开销从关键路径上隐藏掉**。这打破了“路由统计 → 放置决策 → 权重迁移”的时序依赖，实现真正高效的在线均衡。

## 2. 方法论：核心思想、关键技术细节、公式与算法流程

### 2.1 核心思想：残差工作负载预测
- **跨层残差相似性**：由于残差连接，相邻层的隐藏表示非常相似（\(h_\ell = h_{\ell-1} + Attention + MoE\)，更新量相对于隐藏状态本身较小），因此可以用第 \(\ell-1\) 层的输出 \(h_{\ell-1}\) 来预测第 \(\ell\) 层专家的工作负载，而无需等待第 \(\ell\) 层的路由执行。
- **轻量预测器**：不引入任何额外参数或训练。直接复用目标层原有的冻结路由器 \(g_\ell\)：
  - 早期调用：\(\hat G_\ell = g_\ell(h_{\ell-1})\)，在目标层注意力之前执行，得到预路由 logits；
  - 正常调用：\(G_\ell = g_\ell(H_\ell)\)，在路由阶段执行，用于最终 token 分配。
- **工作负载估计**：对早期 logits 应用 top-k 规则，得到预计的 token-to-expert 分配 \(\hat T_\ell(i)\)，聚合成每个专家的预计负载 \(\hat n_{\ell,e} = \sum_{i=1}^N \mathbb{1}[e \in \hat T_\ell(i)]\)。
- **无损保证**：预测结果仅用于专家放置和迁移规划，不改变最终的模型路由决策。正常路由器调用仍然唯一决定 token 分配给哪些专家，因此模型输出与原始推理完全一致。

### 2.2 预算化专家交换规划
- **目标**：在给定预测负载和当前专家-设备映射下，寻找能降低最大 rank 负载的专家交换方案，同时保证交换通信量不超过可用的重叠窗口（即注意力计算时间）。
- **成对交换**：交换两个 rank 上的专家，保持每 rank 专家数量不变，内存占用不变，且旧/新所有者明确，便于回滚。
- **成本模型**：
  - 单次交换估计成本 \(C(s) = \alpha_{a,b} + (S(e_a) + S(e_b)) / \beta_{a,b}\)，其中 \(S(e)\) 为专家权重大小，\(\beta_{a,b}\) 为 rank 间实测带宽，\(\alpha_{a,b}\) 为启动和协议开销。
  - 可用迁移预算 \(B_\ell = \max(0, T_{attn}^{r(\ell)} - \delta)\)，其中 \(T_{attn}\) 为同类型注意力层的实测时间（按注意力类型分别配置），\(\delta\) 为安全裕度。预算按链路和按 rank 分别约束，防止多个交换超订。
- **贪心调度**：
  - 所有 rank 共享全局负载统计向量，从同一初始映射出发；
  - 枚举候选交换对，计算收益 \(\Delta = \Phi(L) - \Phi(L')\)，其中负载目标 \(\Phi(L) = \max_r L_r + \gamma \sum_r (L_r - \bar L)^2\)，剔除非正收益的候选；
  - 按“收益/成本”降序排序，引入确定性次序（层 ID、源/目标 rank、专家 ID 的字典序），确保每个 rank 本地生成完全相同的交换序列，无需广播规划结果；
  - 逐步接受交换并更新负载和剩余预算，直到不平衡度低于阈值或预算耗尽。

### 2.3 算法流程（每层执行）
1. 用 \(g_\ell(h_{\ell-1})\) 预测第 \(\ell\) 层各专家负载；
2. 将专家负载聚合到各 rank；
3. 在预算内构造成对交换计划；
4. 在目标层注意力计算期间执行专家权重迁移；
5. 在 MoE 阶段开始前提交新放置；
6. 用正常路由器进行最终决策并执行 MoE 计算，得到更均衡的负载而不改变输出。

## 6. 主要结论与发现

- **负载均衡效果显著**：FreeBalance 将最大/平均 rank 负载比从 Vanilla 的 2.01–2.04 降低至 1.33–1.37，最多降低 32.8%。
- **端到端延迟收益**：在 Qwen3-30B 的 19 个 LongBench 子集上平均减少 prefill 延迟 13.1%；在序列长度敏感性测试中，TTFT 平均降低 14.7%，且收益随序列长度增长（从 1K 的 11.0% 到 8K 的 23.3%）。
- **迁移开销被有效隐藏**：每层平均隐藏 5.1 个专家的迁移开销，否则这些开销将占关键路径延迟的 8.5%。
- **预测质量可靠**：提前调用与正常路由调用的 logits 余弦相似度在 0.9896–0.9952 之间，top-k 命中率为 0.7419–0.8494，足以支撑放置规划的准确性。
- **自适应预算优于固定迁移数**：固定交换数的最佳策略在 1K/2K/4K 长度下只达到 1.058×/1.087×/1.126× 加速比，而 FreeBalance 自适应平均交换数（1.82–2.68）达到 1.124×/1.126×/1.154×，验证了按可用注意力窗口调节迁移量的必要性。
- **兼容性**：FreeBalance 可以叠加在已有离线均衡方法之上（EPLB + FreeBalance 通常优于单独使用 EPLB），且不改变路由语义，属于无损优化。

## 7. 优点

- **方法原创性高**：首次提出“路由前预测 → 提前迁移”的范式，利用残差网络的跨层相似性构建免训练的工作负载预测器，巧妙地将在线均衡从关键路径中移出。
- **无损推理**：所有预测只服务于专家放置，不干预最终路由决定，保证模型输出与原始推理完全一致，降低了落地风险。
- **轻量与低开销**：不需要额外训练、不增加模型权重；预测仅是一次额外的前向（复用冻结路由器）；规划是确定性贪心算法，可在线运行。
- **精细的预算控制**：成本模型按链路/rank 双重约束，避免过度迁移，且通过确定性排序避免计划广播，通信开销小。
- **实验设计较全面**：覆盖两个模型、多种任务类型、离线/在线基线、序列长度变化、预测与规划质量分析，结论可信度高。

## 8. 不足与局限

- **预测依赖残差相似性**：方法假设相邻层隐藏表示足够相似，但在某些大模型/极端深层结构中，或当层间更新量较大时（如 MoE 稀疏门控导致残差方向变化大），预测精度可能下降，影响均衡效果；论文仅在两个模型上验证，泛化性存疑。
- **实验场景有限**：
  - 只测了 prefill 阶段，未覆盖 decode（生成）阶段，而解码负载模式不同（KV cache、连续批处理），迁移窗口可能更小；
  - 未在跨节点、不同网络拓扑（如 InfiniBand、异构互联）下进行实验，成本模型中带宽参数的场景覆盖不足；
  - 多任务实验仅通过顺序切换子集模拟，未实现真正的混合并发请求。
- **缺乏对超参数的敏感性分析**：安全裕度 δ、负载目标函数中的 γ 等参数会影响迁移决策，但论文未给出不同取值下的结果；profile 一次注意力时间并复用到所有同类型层，忽略了层间差异。
- **公平性可进一步改善**：对比的在线方法为提及实际实验或数值数据，重复次数仅 3 次且未报告方差；EPLB 的 profiling 状态用 420 个样本构建，与其实际部署条件可能不完全一致。
- **没有讨论失败情形或异常场景**：如预测极端不准时如何回退、交换超过预算时的处理、大模型跨机迁移时的安全性等未做详细分析。
