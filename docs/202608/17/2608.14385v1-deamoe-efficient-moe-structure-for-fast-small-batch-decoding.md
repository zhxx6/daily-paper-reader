## 摘要
混合专家（MoE）模型已被广泛采用于实时交互应用，如编程助手、实时音视频交互系统。为了满足这些场景对极低响应延迟的要求，从业者通常采用小批量解码，在这种方式下MoE推理变得受内存限制，并严重受制于专家权重加载瓶颈。然而，这一瓶颈受到的关注有限，现有的解决方案，如训练后权重压缩或预训练期间的细粒度专家设计，要么降低模型精度，要么引入额外的计算和通信开销。为了解决这一问题，我们提出了DeaMoE，一种解码高效的MoE架构，其中专家被分为若干部门，同一部门的专家由于来自同一专业领域而共享大部分参数，此外每个专家包含少量私有参数以体现其独特性。同时，我们为DeaMoE设计了两阶段路由策略以避免冗余加载，在解码过程中大幅提升LLM解码效率。与原始MoE相比，DeaMoE在预训练7B模型上于A40上每步加载权重最多减少50.9%，端到端TPOT加速最高达1.33倍；在微基准测试中，DeepSeek-V3在A40和H100上分别实现最高2.00倍和1.97倍的峰值加速。

## Abstract
Mixture-of-Experts (MoE) models have been widely adopted in real-time interactive applications such as coding assistants, real-time audio-video interaction systems. To meet the extremely low response latency requirements of these scenarios, practitioners commonly employ small-batch decoding, under which MoE inference becomes memory-bound and is severely bottlenecked by expert weight loading. However, this bottleneck has received limited attention, and existing solutions such as post-training weight compression or fine-grained expert design during pre-training either degrade model accuracy or introduce additional computation and communication overhead. To tackle this issue, we propose DeaMoE, a decoding-efficient MoE architecture, in which the experts are grouped into several departments, and the experts belonging to the same department share most parameters since they come from the same professional field, and additionally each expert contains a few private parameters to reflect its uniqueness. Moreover, we design customized two-stage routing strategy for DeaMoE to avoid redundant loading, under which DeaMoE greatly improves the efficiency during LLM decoding. Compared with vanilla MoE, DeaMoE reduces per-step loaded weights by up to 50.9% and achieves up to 1.33 end-to-end TPOT speedup for the pre-trained 7B model on A40, and up to 2.00x and 1.97x peak speedup for DeepSeek-V3 on A40 and H100 in microbenchmarks.

## 1. 论文的核心问题与整体含义

**研究动机与背景：**

- MoE（混合专家）模型被广泛应用于实时交互场景，如代码补全、语音助手、实时音视频交互系统等。这些场景对响应延迟有极严格要求，通常要求毫秒级别的 token 级延迟。
- 为兼顾延迟与吞吐，从业者普遍采用**小批量解码**（small-batch decoding，典型为每步 4–128 个 token）。在这一场景下，MoE 推理从计算受限转变为**内存受限**，瓶颈在于**专家权重的重复加载**——每次解码步中，少量 token 激活多个分散的专家，权重复用率极低，大量时间耗费在从内存搬运专家参数上。
- 随着现代 MoE 模型专家数量激增（如 Kimi-K2 384 个、LongCat 512 个、Qwen3-Next 512 个路由专家），小批量下不同 token 命中同一专家的概率进一步降低，权重加载冗余愈发严重。
- 现有解决方案存在明显不足：
  - **训练后权重压缩**（如 MoLAE、D2MoE、MoE-SVD、MoBE）：可能损害模型质量，且小批量激活大量不同专家时收益有限；
  - **预训练期细粒度专家设计**：依赖大规模专家并行，在小批量/小规模部署场景下难以发挥优势。
- 核心问题：**缺少一种直接针对小批量解码场景、在不牺牲模型质量的前提下降低每步专家权重大小/加载量的 MoE 架构设计。**

## 2. 论文提出的方法论

**核心思想：**

- DeaMoE 提出"**部门（Department）**"概念：将 MoE 层中所有专家按专业领域划分为若干部门；同一部门的专家**共享大部分参数**（部门级共享骨干），每个专家仅保留**少量私有参数**以体现独特性。
- 该设计背后的直觉是：现代 MoE 中已训练的专家存在显著冗余——多个专家可能学习到相似变换，共享"主干知识"，真正的专业化体现在小部分专家特有组件中。将共享部分分解出来复用，可降低冗余加载而无需激进的逐专家压缩。

**架构细节：**

- 在 DeaMoE 中，同一部门 j 内的所有专家共享大型 gate/up/down 投影矩阵 \(W^j_{gate}\)、\(W^j_{up}\)、\(W^j_{down}\)；每个专家 i 额外引入三个私有子矩阵 \(A^g_i\)、\(A^u_i\)、\(A^d_i\)（均为 \(h_{ffn} \times h_{ffn}\) 维）以区分不同专家。
- 专家计算流程（以 gate 投影为例）：先经共享矩阵 \(W^j_g\) 线性变换，再通过激活函数 \(\sigma(\cdot)\)，最后乘以私有矩阵 \(A^g_i\) 并施以 SiLU：
  - \(\hat{g}_i(x) = \text{SiLU}(A^g_i \sigma(W^j_g x))\)
  - \(\hat{u}_i(x) = A^u_i \sigma(W^j_u x)\)
  - \(\hat{d}_i(x) = (W^j_d)^T \sigma((A^d_i)^T x)\)
  - 专家输出：\(\text{DeaMoE}_i(x) = \hat{d}_i(\hat{g}_i(x) \odot \hat{u}_i(x))\)

**两阶段路由策略（关键创新）：**

- 不直接将 token 送到对应的专家，而是**先按部门收集 token**（阶段一），每个部门对其分配到的所有 token **统一执行共享骨干计算**；随后将中间结果**分发给部门内对应专家**，用私有参数做差异化处理（阶段二），最后再统一执行共享 down 投影。
- 效果：部门级共享参数 \(W^j_g\)、\(W^j_u\)、\(W^j_d\) 在每一步只需加载一次，避免了逐专家重复加载同一骨干参数，从而大幅降低内存搬运量。

**训练配方：**

1. **非线性算子**：在部门骨干与专家私有变换之间插入激活函数，避免多层线性叠加损害质量。对比了 SiLU、GeLU、RMSNorm 及无激活，最终选择 **SiLU**（消融实验验证其训练损失最低）。
2. **专家参数初始化**：专家私有矩阵使用**单位矩阵初始化**（torch.nn.init.eye），使每个专家在初始化时等价于其所属部门骨干，避免随机初始化带来的任意偏差；实验显示单位矩阵初始化比随机初始化训练损失更低。
3. **软性分组 Top-k 路由**：k_dept 作为每 token 激活部门数的上限，但不强制每个 token 恰好覆盖 k_dept 个部门（软约束）。强制严格覆盖会扰乱学习到的路由偏好、损害专业化，且实验表明软约束下每 token 平均激活 3.95 个部门，已接近 k_dept=4。

**参数/FLOPs 预算匹配：**

- DeaMoE 通过调整部门数、专家数、k_dept 与 k_expert 等超参数，使**总参数量与每 token FLOPs 与标准 MoE 基线匹配**。例如与 DeepSeek-V3 匹配的配置中，FLOPs 比 0.995、参数比 0.996。

## 6. 论文的主要结论与发现

1. **权重加载显著降低**：以 DeepSeek-V3 匹配配置为例，在 4–64 token 的小批量范围内，每步加载权重仅为基线的 49.1%–62.8%（最高减少 50.9%）。
2. **端到端加速效果**：7.3B 模型在 A40 vLLM 服务中，TPOT 加速 1.02×–1.33×（批量 32 时达到峰值）；且加速比随批量增大呈非单调变化——先升后降，与权重加载比理论分析一致。
3. **同延迟预算下的吞吐增益**：在 30ms TPOT 预算下，支持批量从 64 提升至 96，吞吐提升 1.50×；在 20ms 预算下，批量从 24 提升至 44，吞吐提升 1.83×。
4. **微基准加速**：DeepSeek-V3 在 A40 上峰值加速 2.00×（批量 24），H100 上 1.97×；Qwen3-235B-A22B 在 A40/H100 上分别达 1.74×/1.60×；加速效果与专家规模正相关——专家矩阵越大、复用率越低，收益越明显。
5. **模型质量保持**：DeaMoE-7B 与 Baseline-7B 在 10 个下游任务中表现相当（6 个任务胜出、4 个略低且差距小），困惑度在 PTB 和 WikiText-2 上更低、WikiText-103 上相当。
6. **架构适用边界**：DeaMoE 的优势在小规模模型 + 高带宽硬件（如 H100 + 7B 模型）上会减弱甚至出现轻微回退（0.85×–0.97×），原因是小专家权重易被 L2 缓存复用，权重加载本就不是主要瓶颈。

## 7. 优点

- **问题定位精准**：直接面向小批量解码下的专家权重加载瓶颈，填补了现有 MoE 优化工作（偏重大批量吞吐、训练效率或模型压缩）未充分覆盖的空白。
- **预训练先行思路**：不依赖训练后压缩或重新参数化，而是从架构层面重构 MoE 结构并从头预训练，避免了后验修改的脆弱性，更有利于保持模型质量。
- **参数共享设计巧妙**：将专家分解为"部门共享骨干 + 专家私有变换"，在保持专家多样性的同时有效降低参数冗余；配合两阶段路由策略（先部门后专家），使得共享骨干参数在每步只加载一次，实现了"结构性"的加载量降低而非"压缩性"的。
- **预算匹配公平比较**：在总参数与每 token FLOPs 双重约束下比较 DeaMoE 与标准 MoE，并在推理实验中尽量对齐内核实现与运行配置（复用相同的 Grouped GEMM 原语、同时启用 CUDA Graph），归因清晰。
- **训练稳定性设计周全**：单位矩阵初始化、SiLU 非线性插入、软性分组 top-k 等训练配方均经过消融验证，且提供了深入的分析解释（如初始化时的类恒等映射、软约束下实际覆盖部门数已接近上限等）。
- **实验覆盖多维**：模型质量、端到端服务、微基准、消融四个层面相互印证；微基准覆盖 7B 到 671B 多个规模、Ampere 与 Hopper 两代硬件，论证了方法的可扩展性与硬件普适性。

- **与压缩方法的直接对比缺失**：未与 MoLAE、MoBE、MoE-SVD 等训练后压缩方法进行质量-速度-参数量三维权衡的实验比较，难以判断 DeaMoE 相对这些路线的综合优劣。
- **硬件覆盖有限**：端到端服务测试仅在 A40 上进行，未在 H100 或消费级 GPU 上验证；微基准虽覆盖 H100，但未覆盖批量大于 128 的极端情况。小模型在 H100 上的轻微性能回退也说明该架构并非普适最优，需要更清晰的适用边界刻画。
- **路由与加载的理论分析简化**：权重加载比的计算基于"预期激活专家/部门"的期望，未考虑实际 GPU 内存层次（如 L2 缓存命中率、不同核函数的访存模式差异）对性能的复杂影响。
- **训练数据单一**：仅使用 RedPajama-v1 一个语料，未验证在多样化、更大规模语料上的泛化性。
