## 摘要
在边缘设备上部署大型语言模型（LLM）进行推理，由于严重的内存和带宽限制而具有挑战性。虽然推测解码和混合专家（MoE）已被提出以提高推理效率，但简单地将它们组合往往会带来过多的验证开销和较差的专家重用，限制了它们在内存受限的边缘环境中的有效性。在这项工作中，我们提出了S2-MoE，一种用于边缘设备上MoE推理的高效自推测解码框架。S2-MoE通过路由感知的自适应推测扩展减少冗余验证，通过重用感知的专家门控提高验证效率，并通过共享上下文对齐草稿和目标执行。在llama$.$cpp中实现，S2-MoE在多种MoE模型和边缘设备数据集上，相对于标准自回归解码实现了高达$5.3\times$的加速（平均约$2.0\times$）。代码可在https://github.com/angerybob/S2-MoE获取。

## Abstract
Deploying large language models (LLMs) for inference on edge devices is challenging due to severe memory and bandwidth constraints. While speculative decoding and Mixture-of-Experts (MoE) have been proposed to improve inference efficiency, naively combining them often incurs excessive verification overhead and poor expert reuse, limiting their effectiveness in memory-bound edge settings. In this work, we propose S2-MoE, an efficient self-speculative decoding framework for MoE inference on edge devices. S2-MoE reduces redundant verification through routing-aware adaptive speculative expansion, improves verification efficiency with reuse-aware expert gating, and aligns draft and target execution via shared context. Implemented in llama$.$cpp, S2-MoE achieves up to $5.3\times$ speedup (about $2.0\times$ on average) over standard autoregressive decoding across diverse MoE models and datasets on edge devices. Code is available at https://github.com/angerybob/S2-MoE.

# S2-MoE 论文中文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：在边缘设备（如 Jetson Orin）上部署大型语言模型（LLM）进行推理，面临**严重的内存和带宽瓶颈**。边缘推理通常为单批次或小批次执行，导致参数复用率低，吞吐量受限于参数读取速度。
- **现有技术**：
  - **推测解码（Speculative Decoding, SD）**：通过轻量级草稿模型生成候选 token，再由目标模型并行验证，可提高“输出密度”（每轮生成的 token 数）。
  - **混合专家（Mixture-of-Experts, MoE）**：通过稀疏激活专家，降低“参数密度”（每轮访问的参数量）。
- **核心矛盾**：SD 和 MoE 直接结合在边缘场景中存在严重问题：
  - MoE 中不同草稿 token 可能激活不同专家，导致验证阶段参数复用率低、计算开销显著增大；
  - 被最终拒绝的 token 可能触发额外专家激活，形成**冗余验证开销**；
  - 已有 SD 方法（如 EAGLE-3）基于 token 置信度扩展分支，但置信度无法反映专家级别的验证成本，难以在 MoE 中高效工作。
- **整体目标**：提出一种**自推测解码（self-speculative decoding）** 框架，通过同时降低冗余验证、提高专家参数复用、增强草稿与目标一致性，在边缘设备上显著加速 MoE 模型推理。

## 2. 方法论：S2-MoE 设计

### 2.1 核心思想
三个互补组件协同工作，分别解决三大挑战：
- **路由感知自适应推测扩展**：减少冗余验证；
- **重用感知专家门控**：提高验证阶段的专家参数复用；
- **上下文对齐自推测解码**：降低草稿与目标之间的误差累积，提高接受率。

### 2.2 关键技术细节

#### 组件 1：路由感知自适应推测扩展（Routing-aware Adaptive Speculative Expansion）
- **动机**：在 MoE 中，候选 token 的验证成本取决于其激活的专家集合；两个置信度相近的 token 可能产生差异极大的边际专家开销。
- **期望收益**：对深度为 $k$ 的草稿 token $i$，其接受概率估计为前缀置信度 $p_i = \prod_{j=1}^k p_{i,j}$，期望收益为 $B_i = p_i \cdot T_{\text{AR}}$，其中 $T_{\text{AR}}$ 是目标模型单步解码平均延迟。
- **边际验证成本**：  
  $$C_i = \Delta C_{\text{ver}}(i|S) + C_{\text{draft}}^i$$  
  其中 $\Delta C_{\text{ver}}(i|S) = |E_i \setminus \bigcup_{j\in S} E_j| \cdot T_{\text{exp}}$，$S$ 为已选中的候选集合，$T_{\text{exp}}$ 为单个新增专家的延迟开销（通过运行时测量或离线 profiling 获得）。
- **效用函数与扩展策略**：  
  $$U_i = \frac{B_i}{C_i} = \frac{p_i \cdot T_{\text{AR}}}{\Delta C_{\text{ver}}(i|S) + C_{\text{draft}}^i}$$  
  仅当 $U_i \ge 1$ 时贪心纳入候选，即预期收益超过预期成本。该方法比固定宽度或仅基于置信度的剪枝更能在 MoE 中平衡接受潜力与验证开销。

#### 组件 2：重用感知专家门控（Reuse-aware Expert Gating）
- **动机**：MoE 中相邻 token 往往激活不同专家，并行验证时专家复用率低，导致内存流量增加。
- **步骤**：
  1. **跨 token 专家重要性聚合**：给定一批草稿 token $B$，每个 token $b$ 有置信度权重 $w_b$（高置信 token 权重更大），将专家 logits 加权聚合为 $g_e = \sum_{b\in B} w_b \cdot \ell_{b,e}$。
  2. **全局偏好专家选择**：对聚合得分取 top-cap 个专家 $E^*$（cap ≥ k），限制偏置范围。
  3. **软路由偏置**：对每个 token 的 logits 添加可自适应的偏置 $\lambda_b \cdot \mathbb{1}[e \in E^*]$，其中 $\lambda_b$ 基于 token 的 top-1 与第 $k+1$ 个专家的分数差距确定。偏置主要影响边界专家，不破坏强主导的路由决策。
- **实现**：采用轻量级融合 CUDA 内核，几乎无额外开销。该方法使验证成本不高于原始路由估计，从而保证了组件 1 成本估计的保守性。

#### 组件 3：上下文对齐自推测解码（Context-aligned Self-speculative）
- **问题**：草稿模型独立维护上下文时，预测误差会跨迭代累积，导致长期生成中接受率下降。
- **方法**：草稿与目标**共享同一 KV Cache**。草稿直接读取共享上下文，其 KV 更新被临时保存并在验证前回滚；只有被接受的 token 才提交到共享缓存。这样草稿误差被限制在单个推测步骤内，不会跨步累积。

## 7. 优点

- **针对 MoE 特性设计**：不像传统 SD 仅考虑置信度，还显式建模了专家激活成本，有效解决了 MoE 验证冗余的核心痛点。
- **训练无关且实用**：无需额外训练，直接基于目标模型的轻量化草稿；实现基于 llama.cpp，代码开源，对边缘部署友好。
- **创新性地引入上下文共享**：通过共享 KV Cache 并安全回滚，显著降低自推测误差累积，提高接受率。
- **专家门控设计巧妙**：通过软偏置提高专家复用，且偏置幅度自适应，保持路由质量；成本估计保守，不会低估验证开销。
- **全面的实验验证**：多模型、多任务、多内存配置、消融与敏感性分析齐全，且附有原始数据表格，透明度高。
