## 摘要
低比特量化减少了大型语言模型推理的内存占用和计算成本。然而，高幅值的离群权重可能引发显著的量化误差，降低模型精度。离群值感知量化通过将离群值保留为高精度、量化其余权重来解决该问题，从而形成低比特稠密GEMM路径和高精度稀疏SpMM路径。现有实现将这两条路径在独立的GPU内核中执行，尽管它们共享激活和输出，因此错失了算子内复用的机会，并引入了冗余的全局内存访问。这种低效在内存受限的解码工作负载中尤为明显。我们提出了FlashQuant，一个用于离群值感知W4A16解码的内容共享执行框架。FlashQuant将稠密GEMM和稀疏离群值SpMM路径融合到单个GPU内核中，实现在异构计算中片上复用激活和输出块。它引入了三项关键技术：稀疏-稠密分块，使离群值处理与稠密GEMM块对齐；Tile-COO离群值编码，实现高效稀疏访问并减少共享内存存储体冲突；以及流水线调度，将计算与数据移动重叠。实验表明，FlashQuant降低了离群值处理开销，相较于cuBLAS BF16实现了2.74倍到4.18倍的加速，相较于最强的未融合离群值感知基线最高实现1.53倍加速。

## Abstract
Low-bit quantization reduces the memory footprint and computational cost of large language model (LLM) inference. However, high-magnitude outlier weights can induce substantial quantization errors and degrade model accuracy. Outlier-aware quantization addresses this issue by retaining outliers in high precision while quantizing the remaining weights, resulting in a low-bit dense GEMM path and a high-precision sparse SpMM path. Existing implementations execute these paths in separate GPU kernels, despite their shared activations and outputs, thereby missing opportunities for intra-operator reuse and incurring redundant global-memory accesses. This inefficiency is particularly pronounced in memory-bound decoding workloads. We propose FlashQuant, a content-sharing execution framework for outlier-aware W4A16 decoding. FlashQuant fuses the dense GEMM and sparse outlier SpMM paths into a single GPU kernel, enabling on-chip reuse of activation and output tiles across heterogeneous computations. It introduces three key techniques: sparse-dense tiling, which aligns outlier processing with dense GEMM tiles; Tile-COO outlier encoding, which enables efficient sparse access and reduces shared-memory bank conflicts; and pipelined scheduling, which overlaps computation with data movement. Experiments show that FlashQuant reduces outlier-processing overhead, achieving $2.74\times - 4.18\times$ speedup over cuBLAS BF16 and up to $1.53\times$ speedup over the strongest unfused outlier-aware baseline.

## 1. 核心问题与研究动机

- **背景问题**：大型语言模型（LLM）参数规模持续增长，推理阶段面临着巨大的内存占用和计算开销。低比特量化（如 INT4 权重量化）虽能显著降低内存占用和带宽成本，但高幅值的**离群权重（outlier weights）** 在量化时会产生严重的重建误差，导致模型精度下降。
- **已有解决方案的不足**：离群值感知量化（Outlier-Aware Quantization）通过将少量离群权重保留为高精度（如 BF16）、量化其余权重，将矩阵乘法分解为**低比特稠密 GEMM 路径**与**高精度稀疏 SpMM 路径**（公式：$Y = X \cdot W \approx X \cdot \text{dequant}(W_Q) + X \cdot W_O$）。但现有系统（如 SpQR、SqueezeLLM）在推理时将这两条路径拆分为**独立的 GPU 内核**执行，各自独立加载激活矩阵、独立写回部分输出，导致**冗余的全局内存访问**。
- **核心问题**：在内存受限的自回归解码（decoding）阶段，即使仅保留极小比例的离群权重，也会产生不成比例的延迟开销。论文将这种冗余内存访问识别为离群值量化推理的关键系统瓶颈。
- **整体含义**：论文提出 **FlashQuant**，一个统一的内容共享执行框架，将稠密 GEMM 与稀疏 SpMM 融合进单个 GPU 内核，实现激活与输出数据的片上复用，从而消除冗余内存流量并降低离群值处理开销。

## 2. 方法论：核心思想与关键技术

### 2.1 核心思想：内容共享融合（Content-Sharing Fusion）

- 与常规内核融合（合并生产者-消费者算子）不同，FlashQuant 将**源自同一数学算子**的两条异构计算路径（稠密 GEMM 与稀疏 SpMM）在**统一的瓦片（tile）执行空间**上协同调度，使共享激活和输出块在片上（shared memory/寄存器）被复用，避免全局内存重复访问。

### 2.2 关键技术一：稀疏-稠密分块（Sparse-Dense Tiling）

- 建立统一的 CTA → Warp → Thread 三级瓦片层级，使稀疏路径与稠密路径在对应区域协同工作：
  - **CTA 级**：将输出块对应的稠密与稀疏权重共同分配给同一 CTA，激活瓦片仅加载一次到共享内存，两条路径的部分结果在片上累加后再写回；采用 **Stream-K 工作分配策略**，将 MAC 迭代空间连续分配给持久 CTA，实现负载均衡并保持激活复用。
  - **Warp 级**：稠密路径使用 Tensor Core 执行规整的 MMA 操作；稀疏路径分配到独立 warp，在 CUDA Core 上处理非规整的离群值计算。为保持无冲突累加，每个稀疏 warp 分配**互不相交的输出列集合**；离群处理对内存延迟更敏感，故可为其**分配额外 warp** 以增强延迟隐藏。
  - **Thread 级**：稠密路径遵循 Tensor Core MMA 布局；稀疏路径将激活矩阵按每 8 个线程划分为桶（bucket），以列分桶方式降低共享内存 bank 冲突。

### 2.3 关键技术二：Tile-COO 稀疏编码格式

- 设计目标：让离群值存储与 GEMM 瓦片边界对齐、支持向量化解码、兼容共享内存激活布局、均衡不规则分布下的工作负载。
- **结构组成**：三个数组——`tile_indptr`（瓦片偏移）、`bucket_info`（桶内偏移与数量，uint16）、`packed_outliers`（打包的离群元素，行/列索引用 uint8，值用 BF16/FP16，每四个离群值打包为一个 uint4 元组）。
- **存储开销**：Tile-COO 总存储为 $(N_{\text{tile}}+1)\times4 + N_B\times4 + nnz\times4$ 字节，相比 CSR 的 $(K+1)\times4 + nnz\times12$ 字节，将索引开销从逐元素转为逐瓦片/桶级，大幅减少元数据。
- **稀疏重排序**：
  - **列重排序**：先按非零数降序排列列，再用最小堆贪心分配各列到负载最轻的桶，均衡各桶工作量。
  - **元素重排序**：按目标 bank 组（$gid = \lfloor k/2 \rfloor \% 4$）对桶内元素排序，并采用桶依赖的循环顺序错开不同子 warp 的 bank 访问，降低共享内存 bank 冲突。

### 2.4 关键技术三：流水线调度（Pipelined Execution）

- 采用四级流水线与双缓冲：① 全局内存→共享内存异步拷贝；② 共享内存→寄存器暂存；③ 反量化与离群解码；④ Tensor Core 与 CUDA Core 计算。通过重叠数据搬运与计算隐藏内存延迟。
- **高效离群解码**（Listing 1）：每个线程根据 `bucket_id` 定位共享内存中的激活行，使用双缓冲预取下一个打包离群项；解码出 k 索引、列索引和四个半精度值；用预计算的一次性 swizzle 掩码修正共享内存布局；最后执行四个展开 FMA 操作，将部分和写回共享内存。

### 2.5 实现架构

- **离线阶段**：离群感知量化 → 稀疏-稠密统一瓦片划分 → Tile-COO 编码与重排序。
- **在线阶段**：单内核融合执行，激活、量化权重、离群瓦片加载至共享内存后，稠密路径与稀疏路径并行计算，最终统一写回。

## 6. 主要结论与发现

- **量化加速**：FlashQuant 相对 cuBLAS BF16 实现 **2.74×–4.18×** 加速。

- **扩展性趋势**：离群密度越高、GPU 算力越强，FlashQuant 的相对优势越明显（融合计算代价被更高算力掩盖，而内存流量节省持续有效）。
