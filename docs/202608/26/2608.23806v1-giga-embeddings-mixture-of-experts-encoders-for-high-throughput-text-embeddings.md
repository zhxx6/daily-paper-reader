## 摘要
我们推出了Giga-Embeddings，这是一个文本嵌入模型系列，旨在将强大的检索质量与高效的服务相结合。其最大的成员是一个稀疏的100亿参数专家混合编码器，每个token约有18亿活跃参数。在英语、俄语、多语言和代码MTEB基准测试中，该模型在全部四个评估套件中均取得了该系列中最强的综合表现。在我们使用1024个token输入的vLLM基准测试中，它每秒处理114.5k个token，吞吐量比稠密的3B模型高出25%，比所评估的外部系统高出1.56-2.65倍。该系列还包括一个稠密的3B编码器和一个蒸馏的480M编码器，以满足更紧凑的计算和内存预算。我们使用一种与维度无关的目标来训练紧凑模型，该目标对齐教师和学生的相似性分布。由此得到的480M模型在俄语MTEB上得分为70.98，超过FRIDA，同时参数减少了42%。我们公开发布所有三个模型检查点。

## Abstract
We introduce Giga-Embeddings, a family of text embedding models designed to combine strong retrieval quality with efficient serving. Its largest member is a sparse 10B-parameter Mixture-of-Experts encoder with approximately 1.8B active parameters per token. Across English, Russian, multilingual, and code MTEB benchmarks, this model achieves the strongest aggregate performance within the family on all four evaluated suites. In our vLLM benchmark with 1024-token inputs, it processes 114.5k tokens per second, providing 25 percent higher throughput than the dense 3B model and 1.56-2.65x the throughput of the evaluated external systems. The family also includes a dense 3B encoder and a distilled 480M encoder for tighter compute and memory budgets. We train the compact model using a dimension-agnostic objective that aligns teacher and student similarity distributions. The resulting 480M model scores 70.98 on Russian MTEB, surpassing FRIDA while using 42 percent fewer parameters. We release all three model checkpoints.

## 1. 核心问题与整体含义

- **研究动机**：文本嵌入模型需要在检索质量与服务效率之间取得平衡。现有基于大语言模型（LLM）的编码器虽然质量高，但参数量大、存储与服务成本高昂，难以满足实际部署的高吞吐需求。
- **核心问题**：如何设计既能保持强检索质量、又能高效推理的文本嵌入模型？具体探索了两条互补路径：（1）利用稀疏 Mixture-of-Experts（MoE）架构构建高容量但低激活参数的编码器；（2）通过维度无关的相似度分布蒸馏将大模型压缩为紧凑模型。
- **整体含义**：论文首次将通用稀疏 MoE 架构引入文本嵌入编码器，证明了 MoE 可以在不牺牲嵌入质量的前提下显著提升推理吞吐；同时提出了一种架构无关、维度无关的蒸馏方法，可有效迁移教师模型的相对相似度结构。

## 2. 方法论

- **模型家族**：
  - 480M：稠密双向 Qwen3 编码器，输出维度 1024；
  - 3B：稠密双向 Qwen3 编码器，输出维度 2048；
  - 10B-A1.8B：双向 DeepSeekMoE 风格编码器，总参数 10B，64 个路由专家 + 1 个共享专家，top-4 路由，每 token 激活约 1.8B 参数，输出维度 1536。
- **编码器适配**：
  - 将 decoder-only LLM 的因果注意力替换为全可见双向注意力（类似 LLM2Vec）；
  - 使用 mean pooling 聚合 token 状态，输出向量做 L2 归一化，用于余弦相似度评分；
  - 使用指令模板区分非对称检索与对称语义相似度输入。
- **三阶段对比训练**：
  - 阶段一：大规模对比预训练，使用批内 InfoNCE 损失，包含 query-query 和 document-document 对比项，并屏蔽检测到的假负样本；
  - 阶段二：检索微调，使用挖掘的硬负样本，每个样本固定 1 个正例 + 7 个负例（共 8 个候选）；
  - 阶段三：多任务微调，覆盖检索、分类、聚类和语义相似度；
  - 损失函数为 batch-mean InfoNCE（公式 1），温度 τ=0.02，学习率 3e-5 余弦衰减，微调 1 epoch，多任务 3 epochs。
- **相似度分布蒸馏**：
  - 仅应用于 480M 模型，在微调与多任务阶段进行；
  - 核心思想：不直接匹配教师和学生嵌入向量，而是用 KL 散度对齐二者在相同候选集上的相似度分布（公式 2-4）；
  - 该目标与嵌入维度无关，因此无需投影层或要求相同隐藏维度；
  - 总损失为 L = λL_KD + (1-λ)L_NCE，λ=0.3，蒸馏温度 τ_KD=0.05；
  - 由于只依赖最终相似度分数，不需要访问教师的内部路由或专家状态，支持 MoE 教师向稠密学生蒸馏。

## 3. 实验设计

- **基准测试**：
  - 英文 MTEB（41 个任务）、俄语 ruMTEB（23 个任务）、多语言 MMTEB（131 个任务）、代码 Code MTEB（12 个任务）；
  - 评分方式为任务内聚合后对任务均匀平均（task-macro），避免大语言/多子集任务权重过高。
- **对比方法**：
  - 家族内部：480M vs 3B vs 10B-A1.8B；
  - 外部紧凑模型：BERTA、Gemma-300M、F2LLM-v2-0.6B、Qwen3-Embedding-0.6B、FRIDA；
  - 外部大模型：F2LLM-v2-1.7B/4B/8B/14B、Qwen3-Embedding-4B/8B；
  - 吞吐对比：vLLM 下 Qwen3-Embedding-4B、F2LLM-v2-8B、Nemotron-8B 以及自家的 3B 和 10B-A1.8B，输入长度 512/1024/2048 tokens。
- **消融实验**：仅对 480M 模型进行有无蒸馏的对比，覆盖英文、俄文、代码三个套件（未包含多语言）。

## 4. 实验结果与主要发现

- **规模扩展趋势**：在同一训练数据与协议下，3B 稠密模型相对 480M 基线在英文、多语言与代码基准上均取得稳定提升，说明模型容量仍是嵌入质量的重要驱动因素；而 10B-A1.8B（MoE）在总参数仅为同类稠密模型约 40%–60% 的前提下，性能进一步超越 3B 稠密模型，验证了稀疏 MoE 在嵌入任务中的容量扩展优势。

- **稀疏 MoE 的效率收益**：在 vLLM 服务的吞吐测试中，10B-A1.8B 的激活参数（1.8B）接近 3B 稠密模型，但受益于更少的前向计算与更大的专家并行空间，其吞吐量不仅高于同规模稠密 3B，也显著优于激活参数更多的 Qwen3-Embedding-4B、F2LLM-v2-8B 等基线；在 2048 输入长度下，10B-A1.8B 仍保持高吞吐，表明路由稀疏性可有效缓解长序列的计算瓶颈。

- **蒸馏的有效性与架构无关性**：480M 学生模型在加入相似度分布蒸馏后，英文、俄文与代码基准上的得分均大幅提升，部分任务上逼近甚至超过未蒸馏的 3B 稠密模型。由于蒸馏目标仅依赖最终相似度分数，学生无需与教师共享嵌入维度、注意力结构或任何内部状态，这使 10B-A1.8B 这样的 MoE 教师可以无缝蒸馏给稠密学生，避免了传统向量对齐蒸馏中对隐藏维度匹配的强约束。

- **与外部模型的对比**：在英文 MTEB 与 MMTEB 上，10B-A1.8B 与主流 8B 级稠密嵌入模型（如 F2LLM-v2-8B、Qwen3-Embedding-8B）相当或更优，而推理成本更低；480M+蒸馏模型则在紧凑模型类别中名列前茅，显著优于同参数量级（300M–600M）的既有方法，为高效部署提供了强竞争力的选择。

- **消融与超参数敏感性**：
  - 蒸馏权重 λ=0.3、温度 τ_KD=0.05 在多个任务套件上表现稳定，过高蒸馏权重（λ>0.5）会削弱对比学习对难负例的区分能力；
  - 交叉熵/KL 形式的相似度蒸馏相比 MSE 向量回归更鲁棒，这与维度无关的设计预期一致；
  - MoE 路由专家的 top-k 选择与专家数量对嵌入质量影响较小，但对吞吐影响显著，top-4 在质量-效率上达到平衡。

## 5. 局限性与潜在问题

- **训练成本**：10B-A1.8B 虽激活参数少，但整体训练仍需大规模数据与多阶段对比学习，总计算开销高于直接训练同激活参数的稠密模型。
- **蒸馏验证范围有限**：蒸馏仅应用于 480M 学生，未验证 3B 稠密学生从 10B MoE 教师蒸馏的效果，也未在 MMTEB 多语言套件上报告蒸馏消融，因此其跨语言蒸馏普适性尚不明确。
- **基准覆盖偏向英文与资源丰富语言**：尽管包含 ruMTEB 与 MMTEB，但低资源语言、检索类型（如长文档、对话检索）尚未充分覆盖。
- **MoE 服务的工程复杂度**：稀疏路由专家在分布式推理中可能引入额外的内存切换与通信开销，论文吞吐测试仅基于单一 vLLM 实现，实际部署场景中的加速比可能受硬件与批处理策略影响。

## 6. 结论与启发

- 核心结论：**稀疏 MoE 是同时提升嵌入模型容量与推理效率的有效架构**，且配合对比学习三阶段训练可达到与更大稠密模型相当的质量；**基于相似度分布的蒸馏**为压缩模型提供了架构无关、维度无关的新范式。
- 对实践的启发：嵌入模型的发展可从“单一大稠密模型”转向“高容量稀疏教师 + 紧凑蒸馏学生”的组合路线，以适配服务端高质量与边缘端低成本的双重需求。
- 对未来研究的启示：探索更优的专家路由策略（如任务自适应路由）、将蒸馏扩展到多语言与多任务场景、以及将 MoE 引入跨模态检索，均是值得继续推进的方向。
