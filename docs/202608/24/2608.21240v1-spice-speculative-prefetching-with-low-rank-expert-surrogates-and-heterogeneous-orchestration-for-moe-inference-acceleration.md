## 摘要
混合专家（MoE）模型因其稀疏激活将模型容量与计算成本解耦，在大型语言模型中应用日益广泛。然而，专家参数的巨大规模往往超出GPU显存容量，使得推理延迟主要由用于专家加载的主机到设备PCIe传输所主导。为解决这些挑战，本文提出SPICE，一种面向MoE卸载的推测性预取框架，将轻量级专家预测与置信度感知的CPU-GPU编排相结合。一方面，SPICE构建与目标MoE架构对齐的轻量级草稿模型，利用置信度感知的自适应前瞻算法预取高置信度专家。另一方面，当推测性预测未命中时，SPICE切换至成本感知的CPU-GPU异构编排：低置信度未命中由驻留共享专家与低秩专家（LoRE）替代进行近似，而精确的剩余工作则卸载至CPU，并与正在进行的GPU计算异步并行执行。在DeepSeek-V2-Lite和Qwen2-57B-A14B上跨多种GPU平台评估，SPICE在每输出Token时间（TPOT）上实现了最高3.12倍的加速，且质量损失极小，表明有效的MoE卸载不仅需要预测未来专家，还需决定哪些未命中应被近似、哪些需要精确恢复，以及精确剩余工作应在何处执行。

## Abstract
Mixture-of-Experts (MoE) models are increasingly used in LLMs because sparse activation decouples model capacity from compute cost. However, the large expert parameter footprint often exceeds GPU memory capacity, making inference latency dominated by the host-to-device PCIe transfers for expert loading. To address these challenges, this paper presents SPICE, a speculative prefetching framework for MoE offloading that combines lightweight expert prediction with confidence-aware CPU-GPU orchestration. On one hand, SPICE builds a lightweight draft model aligned with the target MoE architecture, using a confidence-aware adaptive lookahead algorithm to prefetch high-confidence experts. On the other hand, when speculative predictions miss, SPICE switches to a cost-aware CPU-GPU heterogeneous orchestration: low-confidence misses are approximated by the resident shared expert with low rank expert (LoRE) surrogates, while exact residual work is offloaded to the CPU and executed asynchronously in parallel with ongoing GPU computation. Evaluated on DeepSeek-V2-Lite and Qwen2-57B-A14B across diverse GPU platforms, SPICE achieves up to 3.12 speedup in Time Per Output Token (TPOT) with minimal quality loss, showing that effective MoE offloading requires not only predicting future experts, but also deciding which misses deserve approximation, which require exact recovery, and where exact residual work should execute.

## 1. 核心问题与整体含义（研究动机与背景）

**问题背景：**
- 混合专家（Mixture-of-Experts, MoE）模型通过稀疏激活将模型容量与计算成本解耦，已成为扩展大语言模型（LLM）的关键架构。
- 然而，MoE模型的所有专家FFN权重总量远超单GPU高带宽显存（HBM），实际部署中必须将专家权重卸载到宿主DRAM，在推理时通过PCIe总线按需加载。

**核心痛点：**
- 论文量化显示，专家加载延迟占单层执行总延迟的73%–88%，实际计算仅占12%–27%。MoE推理从而从**计算密集型**转变为**I/O密集型**问题。
- 现有专家预取方案存在三个耦合难题：
  1. **预测精度问题**：路由动态随token和层变化，固定前瞻深度要么漏掉有用专家，要么发出过期传输。
  2. **未命中恢复问题**：预测错误时，恢复需要回到关键路径上的I/O，重载权重的成本可能抵消预取的收益。
  3. **带宽与缓存竞争问题**：激进预取会饱和PCIe带宽并占用有限的GPU专家缓存，反而延迟紧急的按需传输或驱逐有用专家。

**整体含义：** 有效的MoE卸载不仅需要预测未来专家，还需要系统性地决策——哪些miss值得近似处理、哪些需要精确恢复、以及精确残差工作应在何处（GPU还是CPU）执行。

## 2. 方法论：核心思想、关键技术细节

SPICE采用**“预测-替代-编排”**三层机制，整体工作流程如下：

### 2.1 推测性预取策略（Speculative Prefetching）
- **轻量级草稿模型**：构建与目标MoE架构对齐的轻量级draft模型，以当前层隐藏状态为锚点，通过**层专属低秩状态转移**递归预测未来层的路由分布。
- **预测公式**：未来层预测路由分布 \( \hat{\pi}^{(l+\delta)}_t \)，取其Top-K作为预测专家集 \( \hat{S}^{(l+\delta)}_t \)，生成预取队列 \( Q_{prefetch} = \bigcup_{\delta=1}^{H} \hat{S}^{(l+\delta)}_t \)。
- **置信度感知的自适应前瞻深度**：
  - **硬件下限** \( H_{min} \)：根据PCIe传输时间与单层计算窗口之比，确定隐藏传输所需的最小时钟提前深度。
  - **置信度阈值**：定义置信度 \( C(\hat{\pi}^{(l)}_t) \) 为预测分布中选中专家的概率质量之和，当 \( C < \tau \) 时提前终止前瞻，避免低质量预测污染缓存。
- **异步预取队列**：通过有界深度、低优先级的copy队列发出H2D传输，防止推测性流量垄断PCIe拷贝引擎。

### 2.2 低置信度替代：共享专家 + LoRE（Low-Rank Expert Surrogate）
- **核心洞察**：利用MoE架构中天然存在的**共享专家**（如DeepSeek-V2、Qwen-MoE），它常驻GPU且提供稳定的层级公共变换。
- **LoRE结构**：对每个层-专家对 \( (l, e) \)，离线训练一个低秩残差模块：
  \[
  \tilde{y}^{(l)}_e = S^{(l)}(h^{(l)}) + B^{(l)}_e A^{(l)}_e h^{(l)}
  \]
  其中 \( S^{(l)}(\cdot) \) 为共享专家，\( B^{(l)}_e \in \mathbb{R}^{d \times r} \)、\( A^{(l)}_e \in \mathbb{R}^{r \times d} \) 为低秩矩阵（\( r \ll d \)），拟合目标为 \( E^{(l)}_e(h) - S^{(l)}(h) \) 的残差。
- **运行时决策**：仅对**低置信度且未驻留**的专家使用LoRE替代，避免同步加载；高置信度或已驻留专家则精确执行。

### 2.3 CPU-GPU异构编排（Heterogeneous Orchestration）
- **问题**：部分高贡献miss既不能近似，也不能承受GPU同步重载。
- **分区策略**：将非替代miss集合划分为 \( M_{fetch} \)（H2D传输后在GPU执行）和 \( M_{cpu} \)（使用宿主驻留权重在CPU上精确执行），通过成本模型考虑当前PCIe压力动态决定划分。
- **执行流程**：
  1. 将当前隐藏状态存入pinned host内存，启动CPU残差执行，同时发起异步H2D传输。
  2. CPU专家计算与拷贝引擎并行，将部分miss成本转化为有用的宿主机侧工作。
  3. GPU传输完成后，在GPU上执行驻留和获取的专家，并将CPU输出合并形成下一层隐藏状态。

### 2.4 算法流程（Algorithm 1）
从当前隐藏状态出发，循环执行：预测路由分布 → 取Top-K专家入队 → 检查置信度决定是否停止 → 投影草稿状态到下一层（通过注意力+预测专家的LoRE输出更新）。直到达到最大前瞻深度或置信度低于阈值。

## 7. 方法亮点与优点

1. **系统性视角**：将“预测”与“miss恢复”统一为一个联合调度问题，超越了单纯预取思路。
2. **置信度感知的自适应前瞻**：同时考虑硬件重叠需求（\( H_{min} \)）与预测质量（\( \tau \)阈值），动态调整前瞻深度，避免固定深度的过度/不足问题。
3. **LoRE残差替代设计精巧**：利用共享专家作为基底+低秩校正，参数开销极小（\( r \ll d \)），且离线训练目标明确（最小化残差近似误差）。
4. **精确与近似的分层决策**：低置信度miss用LoRE近似，高贡献miss用CPU精确执行——实现了“受控误差”与“语义保真”的合理分工。
5. **异步CPU执行与传输重叠**：将部分miss成本转化为有用的宿主机工作，而非单纯等待。
6. **流量控制机制**：低优先级预取队列+高优先级残差流，避免推测性流量干扰紧急传输。
