## 摘要
混合专家（MoE）模型因其在提供高模型容量的同时仅激活每个令牌的一小部分参数，从而提升计算效率，因此非常适合边缘部署。然而，边缘端的MoE推理从根本上受到内存的限制。专家参数通常较大，且由于容量、成本和功耗限制，往往驻留在片外内存中，使得专家加载成为关键路径。我们提出了APEX：自适应专家预取，一种预测性资源管理框架，将专家加载与有用的计算重叠。APEX引入了一个轻量级预取路由器，在注意力块之前预测候选专家，通过学习的置信度模型动态获取额外的专家。这种自适应策略实现了超过99%的重叠准确率，显著优于固定的top-k预取技术。APEX支持两种执行模式：一种保正确性模式，保证精确的路由语义；另一种无停顿模式，通过对可用专家进行操作来消除残余停顿，对应用精度影响可忽略。在多个MoE模型上，保正确性模式相比最先进的基线，将每令牌延迟降低高达26%，并将能量延迟积（EDP）改善高达41%；而无停顿模式在提供额外效率提升的同时，对应用精度的影响可忽略。这些结果确立了自适应、置信度驱动的专家预取作为边缘系统上高效MoE推理的有效方法。

## Abstract
Mixture-of-Experts (MoE) models are attractive for edge deployment because they provide high model capacity while activating only a small subset of parameters per token, improving compute efficiency. However, MoE inference at the edge is fundamentally limited by memory. Expert parameters are large and often reside in off-chip memory due to capacity, cost, and power constraints, putting expert loading to the critical path. We present APEX: Adaptive Expert Prefetching, a predictive resource management framework that overlaps expert loading with useful computation. APEX introduces a lightweight prefetch router that predicts candidate experts before the attention block to dynamically fetch additional experts using a learned confidence model. This adaptive strategy achieves over 99% overlap accuracy, significantly outperforming fixed top-k prefetching techniques. APEX supports two execution modes: a correctness-preserving mode that guarantees exact routing semantics, and a stall-free mode that eliminates residual stalls by operating on available experts with negligible impact on application accuracy. Across multiple MoE models, the correctness-preserving mode reduces per-token latency by up to 26% and improves energy-delay product (EDP) by up to 41% over state-of-the-art baselines, while the stall-free mode provides additional efficiency gains with negligible impact on application accuracy. These results establish adaptive, confidence-driven expert prefetching as an effective approach for efficient MoE inference on edge systems.

**核心问题**
- 固定 top-k 预取策略无法满足边缘 MoE 推理需求——即使平均预测准确率高达 70%–85%，某些层仍可能频繁漏掉专家，产生停顿时延，抵消大部分预取收益。
- 路由不确定性随层和 token 显著变化，静态预取预算无法自适应调整。

## 2. 论文提出的方法论

**核心思想**
- APEX 将专家预取视为一个**置信度驱动的自适应决策**问题：不采用固定的 top-k 预取，而是基于每个 token 的动态置信度，选取 token 相关的额外预取预算，预取 top-(k + δ̂(x)) 专家。
- 在注意力块之前放置一个轻量级**预取路由器**，提前预测候选专家，使专家加载与注意力计算重叠执行。

**关键技术细节**

1. **轻量级预取路由器**
   - 置于每个 MoE 层的注意力块之前，是一个线性层 + softmax，结构与原始路由器相似。
   - 通过蒸馏原始路由器的 softmax 输出分布（KL 散度损失）进行训练，冻结基础 MoE 模型，不修改推理语义。
   - 将原本的"路由→加载→执行"流水线转换为"预测→预取→执行"。

2. **序数逻辑 CDF 置信度模型**（核心创新）
   - 定义覆盖概率 p<sub>δ</sub>(x) = Pr(δ ≥ δ*|x)，表示额外预取预算 δ 足以覆盖原始路由器全部选择的概率，其中 δ* 为 oracle 最小预算。
   - 采用序数逻辑回归建模：p<sub>δ</sub>(x) = σ(θ<sub>δ</sub> − w<sup>⊤</sup>x)，保证单调性（p<sub>0</sub> ≤ p<sub>1</sub> ≤ … ≤ p<sub>N−k</sub>）。
   - 运行时给定目标覆盖率 τ，选择最小 δ 使 p<sub>δ</sub>(x) ≥ τ：
     - 简单 token（高置信度）→ 小 δ，节省通信能耗；
     - 难 token（低置信度）→ 大 δ，提高覆盖率。

3. **两种执行模式**
   - **保正确性模式（Correctness-preserving）**：严格遵循原始路由器决策。当预取漏掉部分被路由的专家时，先异步计算已可用专家，同时加载缺失专家，完整保留原始 MoE 语义。
   - **无停顿模式（Stall-free）**：如果预取集包含全部路由专家，直接执行；否则用原始路由器 softmax 分数最高的可用预取专家替换缺失专家（Algorithm 1），消除停顿但引入极小的近似误差。

4. **两阶段训练**
   - 阶段一：蒸馏预取路由器（KL 损失，仅更新预取路由器）。
   - 阶段二：在保留验证集上收集 oracle δ*，使用累积二值交叉熵（cumulative binary cross-entropy）拟合 CDF 模型。

## 6. 论文的主要结论与发现

1. **自适应预取预算显著优于固定预算**：APEX 在 4 个 MoE 模型上实现了 >97%（τ=0.90）乃至 >99%（τ=0.97）的专家重叠率，远超 ProMoE（常驻 82%–90%）和静态预取方案。
2. **保正确性模式的性能收益显著**：相比最先进的 ProMoE 基线，每 token 延迟降低最高 26%，EDP 改善最高 41%（DeepSeek-16B）。
3. **无停顿模式提供额外效率增益**：在保正确性模式基础上进一步降低 EDP 2%–14%，对 Granite 和 DeepSeek 模型的精度影响可忽略（PPL 增加 <0.11），但对 k=2 的 Phi-7B 精度影响明显。
4. **静态过度预取代价高昂**：过度预取会大幅增加 I/O 传输能耗（如静态 (k+8) 的 I/O 能耗达 97 mJ vs APEX 的 56 mJ），甚至可能使预取流量成为新的瓶颈。
5. **能量优化的本质是**：用少量额外 I/O 传输能量，换取消亡/泄漏能耗的大幅降低（57 mJ → 8 mJ），净收益显著。
6. **开销极低**：额外参数占模型权重 0.022%–0.060%，性能开销 <0.06%。

## 7. 优点

- **系统性创新**：将"固定预取预算"问题重新定义为"置信度驱动的自适应预算选择"问题，并用序数逻辑回归优雅求解，理论保证单调性。
- **严谨的问题分析**：明确指出"高平均重叠率≠无停顿"，引入逐层、逐 token 分析视角，识别 token 级异质性这一关键挑战。
- **双模式设计务实**：区分保正确性（精度敏感场景）与无停顿（性能优先场景）两种部署需求，为不同用户提供灵活选择。
- **实验设计公平且全面**：静态基线与 APEX 共享受训预取路由器，隔离了自适应策略的真实贡献；覆盖 4 个异质模型、多种上下文长度、I/O 带宽与量化精度消融，实验规模充分。
- **评估方法严格可信**：采用 RTL 综合（TSMC 28nm）+ PrimeTime + Ramulator + CHIPSIM 协同仿真，非理想化建模；异步 DMA 传输在统一时间线上受带宽和排队延迟约束。
- **训练开销极小**：预取路由器蒸馏仅需前向传播，训练时间从 10 分钟到 1 小时不等，训练数据仅需通用语料（WikiText），无需任务特定数据。

## 8. 不足与局限

- **无真实硬件原型验证**：论文明确承认 APEX 加速器是通过综合校准的协同仿真评估，而非 FPGA 或硅片原型上的实测；OS 级 DMA 设置和 IOMMU 开销仅用固定每描述符成本建模，端到端 OS 栈建模留作未来工作。
- **无停顿模式对低 top-k 模型不友好**：Phi-7B（k=2）在无停顿模式下精度显著下降（ARC 从 63.4 降至 57.9，τ=0.90），意味着该模式不适合使用很少专家的模型，部署范围受限。
- **训练数据单一**：预取路由器与 CDF 模型仅在 WikiText 上训练，虽然跨下游 benchmark 复用表现良好，但未评估在其他领域文本（如代码、生物医学等）上的鲁棒性。
- **未评估批处理场景**：评估集中于单用户延迟敏感推理，虽然论文声称支持批量并发，但缺少批量场景下无停顿模式精度影响分析。
- **共享专家处理未深入**：DeepSeek 的共享专家不属于自适应预算决策，但论文未分析共享专家与其他机制（如缓存策略）的交互。
- **静态基线的 δ 取值选择**：Granite 和 DeepSeek 分别采用 k+2/k+4 或 k+4/k+8 作为静态基线取值，未给出选择依据，可能对静态基线不完全公平（虽然不同 δ 取值的静态结果也有展示）。
- **精度影响的可迁移性有限**：无停顿模式对精度的微小影响仅验证于特定模型族和 benchmark 集，不同应用场景（如对话、代码生成）中的表现需更多验证。
