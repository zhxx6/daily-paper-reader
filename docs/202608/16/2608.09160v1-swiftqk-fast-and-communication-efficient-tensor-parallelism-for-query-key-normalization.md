## 摘要
查询-键归一化（QK-Norm）提高了现代大语言模型（LLM）的训练稳定性和质量。然而，在张量并行（TP）下，逐层QK-Norm引入了额外的跨GPU通信，因为归一化因子依赖于完整的隐藏向量。我们提出了SwiftQK，一种多GPU RMSNorm内核，仅交换标量归一化统计量，并在无死锁的持久内核中将剩余的逐对（Peer-to-Peer）归约与独立的逐元素计算重叠。对近期LLM的评估表明，与使用全向量All-Gather的标准TP QK-Norm相比，SwiftQK将QK-Norm延迟降低了81.4%–93.9%。在端到端服务中，SwiftQK将TPOT相对于基于All-Gather的基线平均降低29.5%，相对于优化的标量聚合实现平均降低14.3%。

## Abstract
Query-Key Normalization (QK-Norm) improves the training stability and quality of modern Large Language Models (LLMs). However, under Tensor Parallelism (TP), layerwise QK-Norm introduces additional cross-GPU communication because the normalization factor depends on the full hidden vector. We present SwiftQK, a multi-GPU RMSNorm kernel that exchanges only scalar normalization statistics and overlaps the remaining Peer-to-Peer reduction with independent element-wise computation in a deadlock-safe persistent kernel. Evaluations on recent LLMs show that SwiftQK reduces QK-Norm latency by 81.4--93.9% relative to the standard TP QK-Norm using full-vector All-Gather. In end-to-end serving, SwiftQK reduces TPOT on average by 29.5% over the All-Gather-based baseline and by 14.3% over an optimized scalar-aggregation implementation.

## 1. 核心问题与整体含义

- **背景**：QK-Norm（Query-Key Normalization）是近年来大语言模型（LLM）中广泛采用的一种归一化方法，能够显著提升注意力计算的训练稳定性和模型质量。OLMo2、OLMo3、OLMoE等新一代开源模型均采用**逐层（layerwise）** QK-Norm。
- **问题**：在张量并行（Tensor Parallelism, TP）下，逐层 QK-Norm 的归一化因子依赖于**完整隐藏向量**的平方和，而隐藏维度被切分到各 GPU，因此必须引入额外的跨 GPU 同步。标准实现通常使用**全向量 All-Gather**，通信开销极大。
- **影响**：实测表明，QK-Norm 开销在 PP 下仅占总执行时间的 1.3%–1.4%，但在 TP 下可占 19%–30%，且随 GPU 数量增长而恶化（4 GPU 时 Q/K 同步占 QK-Norm 开销的 85%+），严重削弱了 TP 相对于 PP 的延迟优势。
- **核心含义**：QK-Norm 在 TP 下的通信瓶颈是一个**算子级的系统优化问题**，仅靠现有"通信-计算重叠"技术不足以解决，因为 QK-Norm 本身计算量小、通信量大，缺乏足够的计算来掩盖通信延迟。

## 2. 方法论：SwiftQK 的设计

**核心思想**：SwiftQK 是一个通信高效的多 GPU RMSNorm 融合内核，通过**通信量缩减**与**通信-计算重叠**相结合，将 QK-Norm 在 TP 下的开销降至最低。

**关键技术细节**（对应 Algorithm 1）：

- **Phase A：局部平方和聚合（通信量缩减）**
  - 标准 TP 需通过 All-Gather 交换完整 Q/K 向量（O(H) 通信量）；
  - SwiftQK 改为在每个 GPU 上计算**局部平方和**，然后仅跨 GPU 聚合**标量部分和**（O(1) 通信量），以 FP32 累加恢复全局平方和，语义不变。
- **Phase B：通信-计算重叠（延迟隐藏）**
  - 将 Warp 0 专门用于通信路径：执行 P2P 标量归约，通过 IPC buffer 同步读取所有 rank 的部分和；
  - 其余 warp 同时执行**与归约结果无关的 RMSNorm 权重逐元素乘法**，有效隐藏同步延迟。
- **Phase C：最终归一化**
  - 使用全局 RMS 因子对权重乘法后的局部 shard 进行缩放，写回 HBM。
- **死锁安全的持久化执行**
  - 只启动与 SM 上可并发驻留块数一致的有界 grid（≤ Bres × NSM），避免块间循环等待导致死锁；
  - 当 token 数超过驻留块数时，每个块以循环方式处理多 token，形成块级 token 流水线。

  1. **All-Gather-based**：标准 TP QK-Norm，全向量交换，为已评测模型使用的基线；

## 6. 主要结论

- SwiftQK 将 QK-Norm 延迟相对于 All-Gather 基线降低 **81.4%–93.9%**，相对于 MiniMax(fusion) 降低 **29.4%–77.0%**。

- 结论：**通信量缩减 + 通信-计算重叠 + 融合持久化执行**三者的组合是 QK-Norm 在 TP 下取得显著性能优势的关键，缺一不可。

## 7. 优点

- **问题定位精准**：通过系统的性能剖析指出 QK-Norm 在 TP 下是"通信主导"瓶颈，而非单纯的计算或重叠问题。
- **方法简洁有效**：从数学上识别 RMSNorm 只需全局平方和，将 O(H) 激活交换降为 O(1) 标量同步，属于"替换问题本质"而非"掩盖问题"。
- **死锁安全设计**：有界持久内核 + 块级 token 流水线的设计避免了 GPU 内核内 P2P 同步的典型死锁问题，具备实际操作可行性。
- **通信-计算重叠别具匠心**：将权重乘法（与归约无关）作为可隐藏计算，在 warp 级别进行分工，最大化 SM 利用率。
- **数值精度保持**：FP32 累加策略在低精度格式下仍能保持与参考路径一致的精度，消除了通信量缩减可能带来的精度顾虑。

## 8. 不足与局限

- **模型/架构覆盖有限**：实验仅覆盖 OLMo 系列模型；对采用不同位置/不同粒度（如 headwise）QK-Norm 或其他归一化变体的模型，结论的外推性未验证。
- **互联拓扑单一**：仅测试 NVLink 环境；在跨节点或基于网络的 TP（如 InfiniBand）下，延迟模型和重叠效果可能显著不同，SwiftQK 的收益可能被网络延迟放大或缩小。
- **缺少消融研究**：未单独分解"标量聚合"和"通信-计算重叠"各自对端到端性能的贡献，不利于判断方法中哪些组件在何种条件下最具价值。
- **未讨论训练场景**：虽然论文声称SwiftQK有助于训练稳定性，但实验仅限推理/serving，未评估在训练（前向+反向+梯度同步）中SwiftQK的收益和开销。
