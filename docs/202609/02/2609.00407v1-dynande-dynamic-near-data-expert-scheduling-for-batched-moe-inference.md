## 摘要
混合专家（MoE）模型使得大语言模型（LLM）推理的高效扩展成为可能，但在基于神经处理单元（NPU）的系统中部署时面临巨大的数据移动开销。近数据处理（NDP）通过NPU-NDP协同执行提供了一种有前景的方法来缓解这一瓶颈。然而，现有的NPU-NDP MoE系统并未充分考虑到硬件异构性、动态专家级并发性以及批处理推理过程中的时间性专家重用。本文提出了DynaNDE，一个动态近数据专家调度框架，利用NPU-NDP协作来加速批量MoE推理。DynaNDE引入了一个分析性能模型，该模型捕捉协同NPU-NDP执行中的硬件异构性、数据移动成本以及通信-计算重叠。在该模型的指导下，DynaNDE在考虑专家级并发性的同时，跨NPU和NDP确定每层专家调度。DynaNDE还包含一个感知重用的运行时，当专家驻留在NPU内存中时，避免冗余的参数移动。实验结果表明，与最先进的NPU-NDP MoE服务框架相比，DynaNDE实现了显著的吞吐量提升，在预填充和解码阶段的平均加速比分别为2.6倍和2.2倍。

## Abstract
Mixture-of-Experts (MoE) models enable efficient scaling of large language model (LLM) inference but suffer from substantial data-movement overhead when deployed on neural processing unit (NPU)-based systems. Near-Data Processing (NDP) provides a promising way to mitigate this bottleneck via cooperative NPU-NDP execution. However, existing NPU-NDP MoE systems do not fully account for hardware heterogeneity, dynamic expert-level concurrency, and temporal expert reuse during batched inference. This paper presents DynaNDE, a dynamic near-data expert scheduling framework that exploits NPU-NDP collaboration to accelerate batched MoE inference. DynaNDE introduces an analytical performance model that captures hardware heterogeneity, data-movement costs, and communication-computation overlap in cooperative NPU-NDP execution. Guided by this model, DynaNDE determines per-layer expert scheduling across the NPU and NDP while accounting for expert-level concurrency. DynaNDE also incorporates a reuse-aware runtime that avoids redundant parameter movement when experts reside in NPU memory. Experimental results show that DynaNDE achieves substantial throughput improvements over the state-of-the-art NPU-NDP MoE serving framework, with average speedups of 2.6$\times$ and 2.2$\times$ for the prefill and decoding stages, respectively.

# DynaNDE 论文详细总结

## 1. 核心问题与研究动机

- **背景**：混合专家（MoE）模型通过对每个输入 token 仅激活少量专家，有效提升了大语言模型（LLM）的模型容量与推理效率，已成为大规模 LLM 推理的主流架构。
- **核心问题**：MoE 模型参数量巨大，无法全部驻留 NPU（神经处理单元）片内存储，需依赖从外部内存按需搬移专家参数（PMove），导致严重的**数据移动瓶颈**——论文实测中专家参数传输可占据推理执行时间的绝大部分（图 1 显示 PMove 占比极高）。
- **现有解决方案的不足**：近数据处理器（NDP）通过在存储端就近执行专家计算（只需搬移激活 AMove）来缓解此瓶颈，且 NPU-NDP 协同执行有较大潜力。但现有框架（如 MoNDE）的调度策略过于粗粒度：
  - 仅根据 PCIe-NDP 带宽比决定 NPU 端专家数，未建模**硬件异构性**；
  - 未考虑**动态专家级并发度**（同一批中不同专家接收 token 数差异悬殊，且 prefill 与 decoding 阶段差异极大）；
  - 未感知**时间性专家重用**（decoding 阶段热门专家可常驻 NPU 缓存，避免重复 PMove）。

## 2. 方法论：DynaNDE 框架

### 核心思想
DynaNDE 将专家调度视为一个**由解析性能模型引导的在线优化问题**：针对每一 MoE 层，在给定 gating 激活专家集合后，确定哪些专家运行在 NPU、哪些运行在 NDP，使该层总延迟最小。系统结构为 host CPU（运行调度运行时）+ NPU + CXL 互连的 NDP 设备（含 MAC 阵列与 DRAM）。

### 关键技术细节

**（1）三阶段无争用协同执行流程（为避免 PMove 与 AMove 共享 PCIe/CXL 带宽冲突而设计）：**
- Phase 1（NDP 输入暂存）：先将输入激活传输至 NDP；
- Phase 2（NPU-NDP 重叠执行）：NPU 执行"PMove-计算"流水，同时 NDP 执行专家计算，两者并行；
- Phase 3（输出收尾）：所有 PMove 完成后传回输出激活，与 NPU 最后一个专家计算重叠。

**（2）解析性能模型——层延迟公式：**

层总延迟分解为三阶段之和：
- T₁ = 输入激活移动延迟（T_AinMove）；
- T₂ = max( NPU 端 Phase-2 流水延迟, NDP 端总计算延迟 )，其中 NPU 端流水延迟 T_NPU-front = T_PMove(1) + max(∑后续 PMove, ∑前 N-1 个 NPU 计算)；
- T₃ = max(输出激活移动延迟, 最后一个 NPU 专家计算时间)。

**（3）调度算法（Algorithm 1）：**
- 对每个激活专家计算**重用感知偏好分数**：
  - s(i) = T_NDP(i) − (T_NPU(i) + T_PMove(i))，其中 T_PMove(i) 对已在 NPU 内存的专家置 0（体现重用感知）；
- 按分数降序排序专家，则最优 NPU 分配集合必然是排序后的某个前缀——据此进行**前缀扫描（prefix-scan）**，逐次评估每个候选切分点（前 p 个专家上 NPU，其余上 NDP）对应的层延迟，选出最小延迟对应的分配方案；
- 采用前缀扫描而非穷举搜索，将复杂度降为 O(|E| log|E|) 的排序主导复杂度，适合逐层在线决策。

## 6. 主要结论

- DynaNDE 相较现有最先进的 NPU-NDP MoE 框架 **MoNDE**，在 prefill 阶段平均提速 **2.6×**，decoding 阶段平均提速 **2.2×**；
- 相比 NPU-only、NDP-only 和适配后的 HybriMoE，DynaNDE 在几乎所有模型与配置下均有稳定且可观的吞吐提升（prefill 为 1.1×~3.8×，decoding 为 1.1×~30.5×）；
- **解析性能模型引导的调度优于启发式策略**（如固定带宽比划分）；
- **重用感知**能有效避免冗余参数搬移（平均额外 1.1× 增益）；
- 在**硬件异构性、通信-计算重叠与模型特征（如激活差异）的动态变化**下，模型驱动的调度比启发式更具鲁棒性。

## 7. 优点与亮点

- **模型与调度统一**：将硬件异构性（NPU/NDP 吞吐差）、PMove/AMove 成本差异、通信-计算重叠、段内专家并发纳入一个延迟模型，调度由同一模型直接引导，设计与执行一致性好；
- **算法高效可在线运行**：通过排序 + 前缀扫描使调度复杂度控制在 O(|E| log|E|)，并契合 NPU-NDP 共享链路无争用的执行流程，具备实际落地可能；
- **消融设计清晰**：N-DynaNDE 对照组精确分离了"重用感知"的独立贡献，因果归因明确；
- **实验覆盖全面**：覆盖 prefill/decoding 两阶段、3 个不同拓扑的 MoE 模型、批量大小与缓存配置敏感性、多种替换策略，且有调度可解释性分析（NPU-PMove vs NPU-Reuse 分解），不仅给出性能结果还解释机制；
- **报告了硬件开销**：给出 NDP 面积、功耗综合数据，对部署可行性有参考价值。

## 8. 不足与局限

- **缺乏真实硬件验证**：全部性能数字来自周期精确模拟器，未在真实 NPU + CXL-NDP 系统上部署测量，实际性能可能受驱动、调度软件开销等未见因素影响；
- **算力资源未披露**：论文未报告仿真耗时、所遍历的 token 总数与真实服务的差异等，实验成本与可复现性说明不够充分；
- **适用面有限**：仅考虑**单 NDP**配置；多 NDP 时的专家放置、激活路由、负载均衡、跨 NDP 通信等问题被列为未来方向，实际数据中心通常为多设备配置，因此与真实大规模部署仍有距离；
- **专家缓存假设较理想**：NPU 专家缓存命中/替换只按简单比例与固定策略（LFU/LRU/ARC）模拟，未考虑真实系统中有限片上存储与注意力等其余层对内存的竞争，可能高估缓存可用性；
