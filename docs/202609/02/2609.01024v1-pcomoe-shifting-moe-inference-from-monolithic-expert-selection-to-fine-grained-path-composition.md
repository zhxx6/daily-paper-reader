## 摘要
混合专家（MoE）架构通过为每个令牌激活稀疏的专家子集，高效扩展了大语言模型（LLM）的容量。然而，现代MoE推理仍然受到刚性、整体专家抽象的重度制约。现有框架将专家作为原子执行单元进行管理、调度或修剪，这过早地固定了优化边界，并留下了细粒度专家内计算冗余未被充分探索。在这项工作中，我们提出了PCoMoE，一个路径组合执行框架，将MoE推理从粗粒度专家选择转向细粒度路径组合。PCoMoE包含了专家计算的路径级公式、一种兼容性感知的逐层修剪策略以抑制低价值路径组合，以及一个硬件友好的执行引擎，以在严格有限的额外开销下利用可重用的子专家结构。实验结果表明，PCoMoE实现了高达1.31倍的端到端推理加速，同时将模型准确率提升了10%。代码可在 https://github.com/gzyyy0/PCoMoE 获取。

## Abstract
Mixture-of-Experts (MoE) architectures scale Large Language Model (LLM) capacity efficiently by activating a sparse subset of experts per token. However, modern MoE inference remains heavily constrained by the rigid, whole-expert abstraction. Existing frameworks manage, schedule, or prune experts as atomic execution units, which fixes the optimization boundary too early and leaves fine-grained intra-expert computational redundancy underexplored. In this work, we present PCoMoE, a path-compositional execution framework that shifts MoE inference from coarse-grained expert selection to fine-grained path composition. PCoMoE incorporates a path-level formulation of expert computation, a compatibility-aware layer-wise pruning strategy to suppress low-value path combinations, and a hardware-friendly execution engine to exploit reusable sub-expert structures under strictly bounded overheads. Experimental results demonstrate that PCoMoE achieves up to a 1.31x end-to-end inference speedup while enhancing model accuracy by 10%. The code is available at https://github.com/gzyyy0/PCoMoE

## 1. 核心问题与整体含义

- **研究背景**：MoE（Mixture-of-Experts）架构通过按 token 激活少量专家，在扩大模型容量的同时控制推理成本，已成为现代 LLM 服务的关键技术。
- **现有瓶颈**：当前 MoE 推理优化普遍将每个专家视为“原子”执行单元，仅在专家间做调度、剪枝、缓存或旁路，优化边界固定在整体专家层面。
- **被忽视的冗余**：单个 MoE 专家内部包含不同的子变换（如 SwiGLU 的 gate/up/down projection），这些子结构的计算量、语义角色和精度敏感性差异很大，但未被现有方法利用。
- **论文立意**：提出 **PCoMoE**，将 MoE 推理从“选择整个专家”转变为“组合细粒度路径”，通过利用专家内部的冗余结构实现更高的效率与质量平衡。

## 2. 论文提出的方法论

- **核心思想**：把每个 SwiGLU 型 MoE 专家拆成两部分：
  - **扩展侧（expanding side）**：Gate + Up 投影 + SiLU 激活，计算量大，占约 2/3 专家 FLOPs；
  - **投影侧（projection side）**：Down 投影，负责将中间特征映射回隐藏维度。
- **路径化公式**：
  - 单个专家 \(F_e(h) = D_e(U_e(h))\)；
  - 定义路径 \(P_{i,j}(h) = D_j(U_i(h))\)，即“源专家 i 的扩展侧 + 目标专家 j 的投影侧”；
  - 路径空间从 n 个专家扩展到 n×n 的虚拟路径集合：对角线对应原专家路径，非对角线对应新的重组路径；该过程不新增参数。
  - MoE 层输出从专家聚合推广为路径聚合：
    \[
    y = \sum_{(i,j)\in \Pi(h)} \beta_{i,j}(h) P_{i,j}(h)
    \]
    对角线选择时等价于原始 MoE 层。
- **兼容性感知路由**：
  - 对每条路径打分：
    \[
    s_{i,j}(h) = g_{\text{base},i}(h) + b_{i,j} + \lambda g_{\text{tgt},j}(h)
    \]
    其中 \(g_{\text{base}}\)、\(g_{\text{tgt}}\) 为源端/目标端路由先验，\(b_{i,j}\) 为可学习的兼容性偏置。
  - 对角线偏置初始化为 0，非对角线初始化为负值加噪声，保证初始阶段优先使用原始专家路径；
  - 通过迭代结构剪枝将低价值路径剔除，形成逐层的二值活跃掩码 \(M^{(\ell)}\)；掩码按层独立调整，不删除物理参数，只限制推理时的候选路径集合。
- **硬件友好执行**：
  - 推理阶段先将路由矩阵与活跃掩码结合，做 masked top-k 选出活跃路径；
  - 对活跃路径按“扩展侧源”分组，同一扩展侧只计算一次，再分发到不同的目标侧投影；
  - 通过源分组复用，扩展侧计算量从路径数减少为可用源数，显著减少冗余矩阵乘法和内核调用。

## 6. 主要结论与发现

- **效率提升**：PCoMoE 在自回归解码阶段实现最高约 **1.31× 端到端加速**，其中解码最高约 1.305×；Mixtral-8x7B 上 decode 吞吐从 26.50 提升至 34.58 tokens/s，端到端吞吐从 133.43 提升至 172.72 tokens/s。
- **质量提升**：与 Vanilla 相比，PCoMoE 在平均 accuracy 上显著改善：
  - Qwen1.5-MoE：+5.80 点（67.90→73.70）；
  - Mixtral-8x7B：+2.10 点左右；
  - DeepSeek-V2-Lite：+2.46 点左右。
  - 即使与同等微调条件下的 Vanilla-FT 相比，仍保持 +1.6~+2.9 点的优势。
- **细粒度路径有效**：实验证明，将专家内部扩展侧/投影侧重排并对低价值非对角路径做结构化剪枝，不仅没有破坏表达力，反而带来额外精度增益。
- **执行优化重要**：单纯构建路径空间无法获益；必须配合路由、内核融合和源分组调度，才能将算法层面的共享转换为实际吞吐优势。

## 7. 优点

- **视角创新**：打破了“专家不可拆分”的原子化假设，提出专家内部的路径级重组成执行模式，开辟了 MoE 推理的细粒度优化方向。
- **无额外存储开销**：路径组合只重排已有算子，没有新增模型参数，内存 footprint 影响小。
- **系统性设计**：从路径公式、兼容性 gating、结构剪枝到源分组执行引擎，形成了闭环的算法-系统协同设计。
- **保持接口兼容**：可通过固定对角线路径退化回标准 MoE，便于替换现有部署。
- **逐层自适应**：按层敏感度独立决定活跃路径密度，避免一刀切剪枝带来的大范围精度下降。

## 8. 不足与局限

- **适用范围局限**：实验和设计建立在 SwiGLU 风格 FFN 专家上，对非该结构的 MoE 变体需要重新定义算子边界。
- **仅优化 decode 阶段**：Prefill 阶段完全未加速；在强调低首 token 时延或混合 workload 场景中收益可能降低。
- **需要额外微调/离线校准**：PCoMoE 需额外训练兼容性偏置并做渐进剪枝，虽然推理零开销，但带来额外的开发/部署成本。
- **实验覆盖偏少**：只在单卡 H20 上验证，缺少大规模分布式、多用户高并发、批处理更大、模型并行/专家并行下的实测数据。
