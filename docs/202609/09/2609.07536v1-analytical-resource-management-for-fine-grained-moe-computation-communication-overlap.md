## 摘要
分布式混合专家（MoE）推理中的细粒度计算-通信重叠允许在部分计算结果就绪后立即开始通信。然而，执行计算和通信的协作线程阵列（CTA）会竞争流式多处理器（SM）上有限的内存驻留容量。由于驻留CTA通常会在完成前保留其分配的SM资源，无法共驻的CTA必须等待资源，导致波状执行。固定的资源分区无法适应输入大小、路由专家负载和内核配置的变化，可能导致通信积压或降低专家计算并行度。我们提出了一种波量化分析模型和面向依赖耦合重叠管道的启动时资源管理器。利用路由瓦片计数、内核占用率、GPU驻留约束和拆分级就绪依赖关系，它在每次启动前无需候选执行、逐工作负载剖析或内核重编译即可选择通信CTA数量和资源分区。我们将该方法集成到FLUX中的公共COMET A100实现中。我们在四个NVIDIA A100 GPU上，针对三种MoE模型，在GEMM2+GatherRS算子、完整路由器后MoE层和完整模型预填充级别下，采用多种并行策略进行评估。在15个真实p90工作负载中，分析选择器相对于实测或acles实现了3.22%的平均遗憾值，平均求解器开销为0.157微秒。相比COMET，我们的方法在GEMM2+GatherRS算子上实现了2.528倍的几何平均加速，在完整路由器后MoE层上实现了1.771倍，在完整模型预填充上实现了1.185倍，最大值分别为4.218倍、2.584倍和1.439倍。在每个可行的TP=2/EP=2序列长度至少为4096的情况下，我们的实现优于COMET、Megatron core-TE和FastMoE TP+NCCL。

## Abstract
Fine-grained computation--communication overlap in distributed Mixture-of-Experts (MoE) inference allows communication to begin as partial compute results become ready. However, cooperative thread arrays (CTAs) performing computation and communication contend for finite residency capacity on streaming multiprocessors (SMs). Because a resident CTA generally retains its allocated SM resources until completion, CTAs that cannot be co-resident must wait for resources, resulting in wave-like execution. A fixed resource partition cannot adapt to changes in input size, routed expert load, and kernel configuration, potentially causing a communication backlog or reducing expert compute parallelism.   We present a wave-quantized analytical model and launch-time resource manager for dependency-coupled overlap pipelines. Using routed-tile counts, kernel occupancy, GPU residency constraints, and split-level readiness dependencies, it selects the communication-CTA count and resource partition before each launch without candidate execution, per-workload profiling, or kernel recompilation. We integrate the method into the public COMET A100 implementation in FLUX.   We evaluate three MoE models on four NVIDIA A100 GPUs under several parallelism strategies at the GEMM2+GatherRS operator, complete post-router MoE layer, and complete-model prefill levels. Across 15 real-p90 workloads, the analytical selector achieves 3.22 percent mean regret relative to the measured oracle with a mean solver overhead of 0.157 microseconds. Over COMET, our method achieves geometric-mean speedups of 2.528x at the GEMM2+GatherRS operator, 1.771x at the complete post-router MoE layer, and 1.185x for complete-model prefill, with maxima of 4.218x, 2.584x, and 1.439x, respectively. At every feasible TP=2/EP=2 sequence length of at least 4,096, our implementation outperforms COMET, Megatron core-TE, and FastMoE TP+NCCL.

An analytical resource management for fine-grained MoE computation-communication overlap

### 一、核心问题与研究动机

- **背景**：MoE（Mixture-of-Experts）模型通过稀疏激活减小计算成本，但随着模型规模持续增长，专家必须分布在多块 GPU 上，产生了跨设备通信开销。已有研究表明，分布式 MoE 推理中通信开销可占端到端执行时间的 47%。
- **核心矛盾**：为抵消通信开销，已有方法（如 COMET）将计算-通信重叠细化到 split/tile 级别，允许通信在前序 GEMM 部分结果就绪后即开始。但计算 CTA 与通信 CTA 会竞争 SM（流式多处理器）有限的驻留容量。
- **两个关键挑战**：
  - **波状执行**：驻留 CTA 在完成前不会释放资源，不能共驻的 CTA 只能等待，导致执行时间是阶梯式的而非线性的。以"波"为单位，性能随资源配置呈台阶形变化；
  - **依赖-驻留耦合**：通信 CTA 必须等计算公布数据后才能推进，但其驻留又会减少计算可用的 SM，形成闭环耦合。
- **问题定义**：给定工作负载形状、内核占用率和依赖图，能否*不经过逐工作负载剖析*，在启动前直接解析地求出通信 CTA 数 C*，使 GEMM2+GatherRS 算子完成延迟最小化？
- **意义**：静态资源分区无法适应输入 token 数、路由负载分布和序列长度的变化——通信 CTA 过少导致通信积压，过多则压缩 GEMM2 的计算并行度。该问题直接决定了细粒度重叠机制能否成为实际可用的加速方案。

### 二、方法论

论文提出**波量化依赖约束分析模型**（wave-quantized analytical makespan model）与**启动时资源管理器**（launch-time resource manager），核心设计如下：

1. **基本框架：固定运行时、只调 CTA 分配**
   - 复用 COMET 的既有计算内核（GEMM2）与通信内核（GatherRS），不改变 tile 划分、split 级就绪协议、计算量与通信量；
   - 唯一决策变量是通信 CTA 数量 C，据此推出通信驻留 R(C) 与剩余计算容量 P(C)。

2. **资源约束：最小保进度驻留**
   - 驻留约束：R(C) = ⌈C / o_comm⌉（上行取整）。当前 GatherRS 内核每 SM 仅容 1 个通信 CTA，即 o_comm = 1，因此 R(C) = C；
   - 计算容量：P(C) = o_comp × (G − R(C))。当前 128×128 GEMM2 内核每 SM 最多驻留 2 个计算 CTA（o_comp = 2），故 P(C) = 2(G − C)；
   - 增加 1 个通信 CTA ↔ 减少 1 个 SM ↔ 减少 2 个计算 CTA 驻留位，这是整个模型的资源耦合核心。

3. **工作量与波数**
   - 计算工作：单 split 计算 tile 数 W_comp = (∑_e ⌈M_e / T^comp_M⌉) × ⌈⌈N/L⌉ / T^comp_N⌉（按全局 tile 序列分布处理，而非将 split 视为隔离计算阶段）；
   - 通信工作：W_comm = ⌈(M/D) / T^comm_M⌉ × ⌈(N/L) / T^comm_N⌉；
   - 各自波数：
     - V_comp(C) = ⌈W_comp / P(C)⌉
     - V_comm(C) = ⌈W_comm / C⌉

4. **split 级依赖递推**（组成完整流水线时序）
   - 全局 tile 序列下的计算发布时刻：A_s(C) = ⌈(s+1)W_comp / P(C)⌉（前 s+1 个 split 的总计算波数）；
   - 通信单 split 服务时间：q(C) = ρ·V_comm(C)，ρ 为通信波/计算波的相对服务时间比（以固定 C=16 实测获取基准，并随 K 维、tile 尺寸、rank 数缩放，该参数仅在方法初始化时校准一次，不随每次调用重新拟合）；
   - 递推：F_s(C) = max(A_s(C)，F_{s−1}(C)) + q(C)，其中 F_{−1}(C)=0；
   - 预测延迟：T(C) = F_{L−1}(C)，即最后一个 split 的完成时刻；
   - 最终选优：C* = arg min_C∈C T(C)。

5. **运行时流程（Algorithm 1）**
   - CPU 侧循环评估 C = 1…C_max（当前 A100 上 C_max = 16，通过一次性内核族饱和特征确定；扫至 32 无域外改进）；
   - 若同一平台上有多个 C 预测值相同，选出最终计算波中空闲槽数最小（Δ_comp 最小）的候选作为 tie-breaker；
   - 总体开销 O(E + L|C|)，实测平均求解器耗时仅 **0.157 微秒**；
   - 资源管理器插入在通用内核 dispatch 与实际启动之间——只需读取现存 dispatch 选中的内核 tile 形状与驻留上限，GPU SM 数在算子初始化时缓存，不重复查询；
   - 无需候选执行、无需逐 shape 剖析、无需内核重编译。

### 六、主要结论与发现

- **预测精度**：15 个真实 p90 负载上，相对实测 Oracle 平均遗憾 3.22%（最大 10.21%），求解器开销 0.157 微秒；其中 Granite 平均 0.91%、Qwen 7.14%、DeepSeek-V2-Lite 1.60%。
- **算子级（GEMM2+GatherRS）**：相对 COMET 几何平均加速 2.528×（最大 4.218×）；TP=2/EP=2 下 Qwen real-p90 在 S=16384 时达 3.857×。
- **层级（post-router MoE layer）**：几何平均加速 1.771×（最大 2.584×）；因 AllGather+GEMM1 与激活保持不变，加速比低于算子级属预期行为。
- **完整模型 prefill**：几何平均加速 1.185×（最大 1.439×）；TP=2/EP=2 下对 Granite/Qwen/DeepSeek-V2-Lite 的几何平均加速分别为 1.336×/1.211×/1.232×。
- **系统间对比**：在每个可行且 S ≥ 4096 的 TP=2/EP=2 点上，本方法都优于 COMET、Megatron core-TE 与 FastMoE TP+NCCL。短序列（S=1024 时）各系统互有快慢，说明此类分析方法在 tile 波数足够时能显现结构性优势。
- **结论主张**：在固定内核算法不变的前提下，仅对计算/通信 CTA 做启动前的解析式重分配，即可有效化解依赖-驻留耦合冲突，将"已暴露的并发"转化为"有效的重叠"。

### 七、优点

1. **免剖析的解析建模**：直接以 workload 元数据 + 驻留限制推导最优 CTA 分配，规避候选启动耗时、运行时调参与逐 shape 调参表；

2. **运行开销极低**（~0.157 微秒/次），在小算子调用上也足够"便宜"；

3. **方法通用性强**：模型只依赖可具象化的 tile 波/wave 与 split 级依赖 DAG，作为方法论可推广到其他计算-通信重叠对（文中明确列出迁移到新架构/新算子需要重新实例化的参数）；
4. **资源耦合结构刻画**：以"加 1 通信 CTA ↔ 少 1 个计算 SM = 2 个计算 CTA 容量"这样的显式代价把握了这一资源-依赖交织的核心机制，具有清晰的因果解释力；
5. **实验设计严谨**：三级测量边界 + 多模型/多路由/多序列长度 + 多基线 + 全链路公平性验证，逻辑严密；
6. **正确性保持**：方法不改变任何数据路径，只减少因 CTA 资源分配不当造成的空闲等待与排队尾延迟。

### 八、不足与局限

1. **架构覆盖有限**：仅验证 A100 单节点/NVLink 场景；其他 GPU/互联版本（H100、多节点 RDMA 网络）未做实测或迁移验证；
2. **模型 / 输入覆盖有限**：
   - 未评估 decode（自回归/在线服务）场景，而解码是以小 batch 和内存带宽为主的负载；
   - 真实路由切面只取了 p50/p90 两个代表性快照，没有覆盖大范围路由极端倾斜或概念漂移后的分布变化；
   - S=16384 的 DeepSeek-V2-Lite 因为显存容量不足 OOM，部分网格出现了空缺；
3. **基于手工校准的 ρ 参数**：ρ_ref 是在一个固定工作点上测量后经 K/tile/rank 缩放推算的，若输入维度远超校准范围，可能引入系统偏差（虽然 Qwen 的 regret 水平——最大 10.21%——暗示仍可实现可用的精度）；
4. **静态分区逻辑假设与可实现性**：模型对"同波可展开为完全并行"的假设，在真实内核调度存在 SM 不完全填充/调度延迟时会有小偏差；论文依靠 tie-breaker 规则弱化了该风险，但是否彻底消解尚未讨论；
5. **缺少与更强动态资源分配机制的对比**：只对比了固定 C 的 COMET 与其他基于集合通信的 baseline，未对比"基于即时测量的

基于即时测量的自适应轮询/动态驻留调整机制”进行对比。因此，本方法的优势是在“启动前一次性决定”这一策略框架下确立的，并未检验“如果允许在运行中根据真实队列深度、SM 占用率或通信积压动态调整通信 CTA 数，能否进一步逼近 Oracle”；换言之，静态解析模型相对动态反馈控制的上界尚未被刻画，其适用边界仍有一定模糊性。

### 九、总体评价与展望

本文在细粒度 MoE 计算-通信重叠这一具体系统问题上提出了一个轻量、可解释且近乎零开销的解析式资源分配方法。其核心贡献不在于发明新的内核或新的重叠协议，而在于揭示并形式化了“CTA 驻留波次”与“split 级依赖”之间的耦合关系，将问题从经验调参转化为可解析求解的离散优化问题。方法在 A100 + NVLink 单节点环境下表现稳健，算子层最高超过 4× 加速、完整 prefill 仍有约 1.2× 的端到端收益，且预测误差控制在可接受范围，具有实际部署潜力。

从更广阔的视角看，该工作示范了一条值得借鉴的技术路线：在大规模并行系统中，与其不断增加动态反馈机制的复杂度，不如先深入理解底层执行模型的结构化约束，用显式的波次与容量模型换取极低的控制开销。未来工作至少有三个自然延伸方向：一是将模型迁移到 H100/多节点 RDMA 等异构环境中，重新实例化驻留容量与服务时间参数，验证其跨架构可迁移性；二是将分析对象从 prefill 扩展到 decode 场景，处理小 batch、内存带宽受限时的资源竞争；三是将类似思路推广到 MoE 训练前向/反向、专家并行与序列并行的组合等更复杂的计算-通信依赖图上，构建统一的解析式调度层。

总体而言，这是一篇问题定义清晰、方法可复现、实验边界严谨的系统论文，虽然在架构覆盖与动态对比上留有空白，但就其界定的范围而言，结论可信，贡献扎实，对 MoE 推理系统中的资源-通信协同设计具有明确的参考价值。
