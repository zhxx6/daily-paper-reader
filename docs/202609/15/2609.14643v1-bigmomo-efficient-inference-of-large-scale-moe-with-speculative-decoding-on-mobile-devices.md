## 摘要
混合专家（MoE）模型扩展了智能手机上语言模型的能力，但专家卸载仍受限于有限的 DRAM 容量和高昂的数据移动开销。顺序式 token 路由将专家执行与碎片化的闪存读取及多阶段 NPU 准备耦合在一起，使稀疏计算因权重传输而停滞。每次传输仅服务少量 token，执行便继续推进。我们利用投机解码的多 token 验证窗口，将专家移动与单 token 执行解耦，从而实现权重复用、连续闪存读取以及加载-计算重叠。我们提出 BigMoMo，一个移动端 MoE 运行时，它在整个内存层次结构中利用这一窗口。它根据接受率、路由影响和移动成本来剪枝投机分支和专家激活；根据运行时共同加载模式重新组织闪存上的专家；并批处理就绪专家，以将 NPU 计算与待处理的传输重叠。在两个移动平台的四个 MoE 模型和五个基准测试上，BigMoMo 相较于按需自回归卸载实现了平均 4.83 倍的解码加速，相较于最佳投机 MoE 基线实现了 1.82 倍的加速，支持高达 30B 参数的 MoE 模型。

## Abstract
Mixture-of-Experts (MoE) models expand language model capacity on smartphones, but expert offloading remains constrained by limited DRAM capacity and costly data movement. Sequential token routing couples expert execution to fragmented flash reads and multistage NPU preparation, leaving sparse computation stalled on weight transfers. Each transfer serves few tokens before execution moves on. We exploit the multi-token verification window of speculative decoding to decouple expert movement from single-token execution, enabling weight reuse, contiguous flash reads, and load-compute overlap. We present \textsc{BigMoMo}, a mobile MoE runtime that exploits this window across the memory hierarchy. It prunes speculative branches and expert activations using acceptance rates, routing impact, and movement cost; reorganizes on-flash experts according to runtime co-loading patterns; and batches ready experts to overlap NPU computation with pending transfers. Across four MoE models and five benchmarks on two mobile platforms, \textsc{BigMoMo} achieves mean decoding speedups of $4.83\times$ over on-demand autoregressive offloading and $1.82\times$ over the best speculative MoE baseline, supporting MoE models up to 30B parameter.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：个人智能（personal intelligence）推动在手机端直接运行 LLM，MoE 通过"稀疏激活"在计算量增长有限的前提下扩展模型容量。但 MoE 的**总参数量**往往超出移动端 DRAM 容量（通常 <24 GB，且实际可用更少，因为要与 OS/后台共享）。
- **现有方案及其失效**：主流做法是**专家卸载**（expert offloading），即把共享权重与高频专家留在主存、其余专家放在 Flash（UFS）中按需加载。这套思路在 CPU–GPU 服务器平台上有效，因为主机–设备带宽高、数据通路只有两层，预取容易与执行重叠。
- **移动端的三个结构性障碍**：
  1. **专家搬运带宽受限**：DRAM 容量与带宽（LPDDR5X ~78 GB/s）远低于服务器，更多专家必须留在外部存储，动态路由导致频繁且漫长的搬运。
  2. **不规则 Flash 访问开销高**：UFS 带宽仅约 4 GB/s，且对访问粒度与连续性极其敏感；稀疏动态的专家请求转化为碎片化读，严重欠利用存储带宽。
  3. **多级执行路径**：NPU（Qualcomm Hexagon）要求先把权重映射进受限的 **NPU buffer**，再搬到 **VTCM**（8 MiB 片上 scratchpad）做布局转换/反量化后才能上 HMX 计算，产生流水线气泡。
- **核心洞察**：MoE 的"参数解耦"只解决了容量问题，**专家搬运仍与逐 token 路由顺序耦合**。作者主张从**模型级参数解耦**转向**系统级数据移动解耦**，而**投机解码的多 token 验证窗口**天然提供了放大执行粒度的机会：
  - 复用友好的专家搬运（多个 draft token 共享一次专家加载）；
  - 对 Flash 友好的访问（一轮验证内聚合碎片读为连续读）；
  - 跨阶段搬运重叠（更多专家计算可与搬运并发）。
- **整体意义**：证明移动端高效智能不必只靠"缩小模型"，通过把数据移动从顺序专家执行中解耦，30B 级 MoE 也能在手机上高效部署。

## 2. 方法论

### 2.1 核心思想
把专家搬运的执行粒度从**单 token** 扩展到**投机验证窗口**，使多个 token 的专家请求同时可见，从而获得权重复用、连续 Flash 读、加载–计算重叠三类机会；再针对"低价值投机 token 引入无用专家搬运""静态放置无法适配动态 Flash 访问""不同层级专家就绪时间不一造成 NPU 空转"三个实现问题，设计三项协同机制。

### 2.2 技术细节

**（A）复用导向的专家搬运准入（§4.2）——两级剪枝**
- **接受率感知的节点剪枝**：对树深度 $h$ 用离线校准集统计的历史接受概率 $\hat{p}_h$，结合 draft 模型的路径置信度，定义节点价值
  $$V_d=\hat{p}_{h(d)}\prod_{u\in\text{path}(d)}q_u$$
  按 $V_d$ 降序保留**累计价值占比 ≥ ρ** 的最小节点集合。
- **层级感知的专家剪枝**：定义专家 $e$ 的**路由影响**
  $$I_e=\sum_{d\in D_e}V_d\cdot\min_{j\in T_d\setminus\{e\}}|s_{d,e}-s_{d,j}|$$
  即被低价值节点选中、或存在路由分数相近替代者的专家影响更低。再离线剖析不同专家大小在各内存层级上的搬运延迟作为**移动成本 $C_e$**，定义剪枝优先级 $P_e=\Delta I_e/C_e$，在**累计路由影响预算 τ** 下迭代剪枝；被剪专家的路由权重**重分配给路由分数最接近的保留专家**，每步更新节点–专家分配并重算 $\Delta I_e$，保证每个节点至少保留一个专家。

**（B）运行时自适应的 Flash 专家组织（§4.3）**
- 用**超图**建模最近 $K$ 轮的共同加载关系：专家为顶点，一轮验证中同层共同加载的专家构成超边 $M^k_l$。
- 为每条超边在所有可容纳 $|M^k_l|$ 个专家的连续 Flash 区域中，选择**驻留专家集合与 $M^k_l$ 重叠最大**的区域作为**锚区域 $A^k_l$**。
- 估计 Flash 读时间：$T^k_l=T^{Flash}_S(A^k_l)+\sum_{e\in M^k_l\setminus A^k_l}T^{Flash}_S(e)$（锚区连续读 + 区外碎片读）。
- 候选交换 $(e_i,e_j)$ 的收益按最近 $K$ 轮历史累计读时间削减评估：
  $$B_l(e_i,e_j)=\sum_{r=k-K+1}^{k}\left(T^r_l-\tilde{T}^r_l(e_i,e_j)\right)$$
  执行**收益最大的正收益交换**（锚区内非成员专家 ↔ 锚区外的请求专家），保持总存储占用不变；**只在两个专家都已加载进共享 DRAM 后**才执行交换写入，避免为搬迁而额外读 Flash；当有延迟敏感的 Flash→DRAM 加载请求到达时**挂起搬迁写入**。

**（C）跨层级搬运调度（§4.4）**
- **VTCM 双缓冲**：VTCM 划分为两个交替权重缓冲 + 128 KiB 激活/输出区；就绪专家按缓冲容量组织成计算组，超大专家沿输出维 $N$ 以 32 的倍数切块；计算批权重打包为连续 128 B 向量并跨 VTCM bank 分布以并行喂给 HMX；HTP DMA 搬入量化权重，HVX 负责反量化。
- **调度规则**：在调度点 $t$，对 DRAM 驻留专家估计就绪时间 $\tau^{map}_{e,t}$（NPU buffer 映射残余延迟），Flash 驻留专家还需加上 Flash→DRAM 加载延迟；下一个就绪时刻 $\tau^{next}_t=\min_{e\in E^{pending}_t}\tau^{map}_{e,t}$；未覆盖搬运时间
  $$R_t=\max\left(0,\ \tau^{next}_t-W_t\right)$$
  其中 $W_t$ 为残余 HMX 计算窗口。组选择为
  $$b^\star_t=\begin{cases}\arg\min_{b:T^{VTCM}_b\le W_t,\ T^{HMX}_b\ge R_t}T^{HMX}_b, & \text{存在这样的 } b\\[4pt]\arg\max_{b:T^{VTCM}_b\le W_t}T^{HMX}_b, & \text{否则}\end{cases}$$
  即优先选能覆盖 $R_t$ 且执行时间最短的组，否则选执行时间最长者尽量填补空隙；初始阶段为已驻留 NPU buffer 的 8 个最常激活专家预构建计算组，新就绪专家动态加入后续组。
