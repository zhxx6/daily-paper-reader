## 摘要
在消费级硬件上进行混合专家（MoE）推理受限于权重内存：一个35B级模型在4比特下为19.5GB，而稀疏性减少的是每个token的计算量，而非必须驻留的字节数。简单地将权重卸载到SSD本身无济于事，因为第N+1层的专家必须在第N层输出存在之前就被选定，所以读取无法足够早地开始以被计算掩盖。我们提出Edge0，一种流式MoE推理引擎，它通过预路由器弥合这一差距：每层的一个头提前一个token预测下一层的路由，且该预测被直接用作路由本身，因此暂存的专家集合等于路由集合，且不会丢弃任何内容。一个未合并的恢复LoRA在学生路径上训练，弥补了因int4量化和路由替换而损失的质量。在单台24GB机器上，Edge0在3GiB峰值活动内存内以20tok/s服务一个35B MoE，在五个公开基准上平均与其fp16教师模型相差仅几个百分点。一个8B档位可在同一框架上运行，且该框架、检查点和适配器均已开源。

## Abstract
Mixture-of-experts (MoE) inference on consumer hardware is bounded by weight memory: a 35B-class model is 19.5GB at 4-bit, and sparsity shrinks the compute per token, not the bytes that must be held. Naive offloading to SSD does not help on its own, because layer N+1's experts must be chosen before layer N's output exists, so the reads cannot start early enough to hide behind compute. We present Edge0, a streaming MoE inference engine that closes the gap with a prerouter: a per-layer head predicts the next layer's routing one token ahead, and the prediction is consumed as the routing itself, so the staged expert set equals the routed set and nothing is dropped. An unmerged recovery LoRA, trained on the student path, pays back the quality lost to int4 quantization and routing replacement. On a single 24GB machine, Edge0   serves a 35B MoE at 20tok/s inside 3GiB of peak active memory, within a few points of its fp16 teacher on average across five public benchmarks. An 8B tier runs on the same framework, and the framework, checkpoints, and adapters are open source.

# 论文总结：The Other Half of the Memory Wall

## 1. 核心问题与整体含义

- **背景（内存墙）**：1995 年 Wulf 与 McKee 提出"内存墙"——处理器性能增长快于 DRAM，机器越来越多周期耗在等待内存上。三十年后的 AI 推理面临同一堵墙，且算术关系对本地部署尤为不利：解码阶段每读取一字节权重只做少量 FLOPs，瓶颈是"字节数"而非算力。
- **两类内存数据被区别对待**：
  - **状态（KV cache）**：动态增长，业界已用 MLA、稀疏注意力、线性状态模型、分页等方法大幅压缩。
  - **权重（静态）**：训练结束即固定，动辄数十 GB，业界主流应对是"搬进数据中心"，用专家并行/分片承载。
- **本地部署两条常规路径在 35B 规模均失效**：
  - 量化在 4-bit 触底，低于 4-bit 误差急剧增大且后处理无法恢复。
  - MoE 稀疏性只减少**计算量**（35B 激活约 3B），不减少**必须驻留的字节数**（4-bit 仍 19.5 GB），在 24 GB 桌面上几乎挤占整机内存。
- **朴素 SSD 卸载无效的根本原因**：第 N+1 层的专家必须在第 N 层输出产生**之前**被选定，读取无法足够早启动以被计算掩盖，导致每 token 每层都卡在磁盘延迟上。
- **论文主张**：权重的"另一半内存墙"本质是**存储放置决策**。Edge0 把专家权重放在 SSD，用"可训练预路由"把加载藏到计算之下，从而在消费级机器上服务 35B 级 MoE。

## 2. 方法论

### 2.1 核心思想
- 专家权重常驻 SSD，按需 mmap 流式加载，峰值内存由**活跃专家集**而非参数量决定。
- 用**预路由器（prerouter）** 打破"下一层专家依赖上一层输出"的串行依赖：每层头提前**一整个 token** 预测下一层路由，且**预测结果直接作为路由本身**。
- 配合**未合并恢复 LoRA**，一次性补偿 int4 量化与路由替换带来的质量损失。

### 2.2 关键技术细节
- **提前一 token 而非一层**：Pre-gated MoE 在同 token 内选下一块专家，需每层同步与头评估，会排空 GPU 流水线（本引擎 30–100 ms/步），反而慢于普通 LRU 基线；一 token 的提前量使头评估移出每层关键路径，每步仅一次 flush 即可预测所有 staged 层（35B 为 32 层，8B 为 16 层）。
- **预路由头结构**：每层 `fc1 → erf-gelu → fc2`，加一条从下一层 router 权重 warm-start 的线性残差路径（默认零初始化）。输入为隐藏状态拼接两个 top-k one-hot（本层当前 token 的实际路由专家 + 上一 token 的实际路由专家），维度 `d_model + 2E`：
  - 35B：2048 + 2×256 = 2560，隐宽 512；33 个头（owner 6–38），消费层 7–38，即 40 层中 32 层靠预测流式。
  - 8B：1536 + 2×128；16 个头（owner 7–22），消费层 8–23，即 24 层中 16 层。
  - 头以 fp16 运行（训练导出精度）。
- **预测即路由**：解码时 MoE 层用预路由器 logits 取代原 router，走同一套 `softmax-topk` 或 `sigmoid-group` 数学，因此**暂存槽位与实选专家集按构造完全一致，无需丢弃**，消除了预门控系统运行时的覆盖-质量权衡；近似代价被转移到训练阶段一次付清。
- **特征漂移问题**：头输入包含"本层实际执行的路由"，训练时是基础 router 的选择，解码时是头自身的预测。头不为此重训，而由恢复 LoRA 在学生路径（含预路由）上训练来吸收该分布偏移。
- **四种执行路径**（数学契约统一为 `down(silu(gate(x))·up(x))`，逐元素对比反量化参考，相对 L2 < 1%，实测 ≈0.24%）：
  1. **exact**：去重按需构建、堆叠、量化 gather，正确性基线。
  2. **staged**：固定槽位双缓冲，解码主力；路由索引经槽表映射，索引不出 GPU；重复专家集复用计算图，`incr stack` 原地更新 sticky-slot 张量，只重写变化的专家而非重建整层 9 个堆叠张量。
  3. **hot**：每层固定 LRU 热专家，命中走堆叠 gather，未命中回落 exact。
  4. **whole-layer**：prefill 时整层一次性加载（per-layer 堆叠布局使之为 9 次直接读），CPU 加载与上一层 GPU 执行重叠。
- **未合并恢复 LoRA**：服务形式为 `y = W4bit(x) + αr BAx`，作为并行 delta 计算，4-bit 基础字节不动。合并再量化的失败是**算术性**的：LoRA delta 的 RMS（10⁻³）低于 4-bit 分组步长，注意力投影仅 34% 效果存活、dense 投影 2%、logits 层 18%。未合并路径仅增加 42 MB 适配器权重，解码时间无可测增加。
- **训练三阶段**（全部在 4-bit 部署检查点的 bf16 反量化重建上、基础冻结）：
  1. **Phase 1 蒸馏头**：仅训练预路由头，损失模仿下一层真实 router（学预测路由而非拟合文本）。
  2. **Phase 2 学生路径 SFT**：LoRA 挂到 attention、linear-attention、共享专家投影（不挂路由专家，因其需可替换），全前向以预路由激活，约 200 万行教师生成文本。仅蒸馏+学生路由的检查点会输出重复崩溃文本，加上 SFT 后可产生连贯输出。
  3. **Phase 3 on-policy 蒸馏**：在约 20 万行（SFT 语料的 1/10）学生自生成文本上，由原 fp16 基础打分，经服务路径取梯度；目标为 reverse KL（模式寻求），应用于教师 top-k token，top-k 外质量以 tail 项承载而非丢弃。
- **迭代经济性**：换路由宽度只需替换适配器文件。35B 档从基础 K=8 收窄到 K=4，在 16 GB 机器同会话 A/B 中解码近翻倍（3.3 → 6.4 tok/s），且质量保持。

## 6. 主要结论与发现

- **存储放置而非压缩才是这堵墙的解法**：在 4-bit 已触底、MoE 稀疏只省算力不省字节的前提下，把静态权重放入 SSD 并以预路由掩藏加载，可在 24 GB 机器上服务 4-bit 下约 19.5 GB 的 35B 级 MoE，峰值内存由活跃专家集而非参数量决定。
- **"提前一 token"是预路由可行的关键粒度**：提前一层会因每层同步与头评估排空 GPU 流水线，反而慢于普通 LRU；提前一整 token 使头评估脱离每层关键路径，每步仅一次 flush 即可覆盖全部 staged 层。
- **预测即路由消除了运行时权衡**：让预路由器 logits 直接取代原 router，使暂存槽位与实选专家集按构造一致，无需丢弃或覆盖，近似代价被一次性转移到训练阶段。
- **特征漂移可由恢复 LoRA 吸收**：头输入中"实际路由"在训练/推理间的分布偏移，不需要重训头，而由学生路径上的 LoRA 在 SFT 与 on-policy 蒸馏中补偿；仅蒸馏 + 学生路由会输出重复崩溃文本，加入 SFT 后恢复连贯。
- **未合并 LoRA 在算术上必要**：LoRA delta 的 RMS 低于 4-bit 分组步长，合并再量化会使注意力投影仅 34%、dense 投影仅 2%、logits 层仅 18% 的效果存活；保留为并行 delta 仅增加约 42 MB 适配器权重且解码无可测开销。
- **路由宽度可后验调节**：换适配器即可改变 K，35B 从 K=8 收窄到 K=4 在同会话 A/B 中解码近翻倍（3.3→6.4 tok/s）且质量保持，说明部署期存在"质量—速度"的连续旋钮。
- **流水线各组件贡献可量化**：`incr stack` 带来约 +34% 解码；native routing 相对完整流水线由 6.8 提升至 12.5 tok/s；禁用预路由器后 35B 降至 19.9 tok/s；LRU 从 64 扩到 1024 bundles 仅增约 0.9 GiB 即达 31.8 tok/s。

- **质量对照面窄**：缺乏与主流 4-bit 量化 + 合并基线、以及与其它 KV/权重压缩路线的同条件横向对比，难以判断 Edge0 相对既有方案的整体优势区间。
- **依赖 SSD 延迟与带宽假设**：方法有效性建立在"每 token 每层的加载可被一次 flush 的预测提前量掩盖"之上；若 SSD 带宽下降、活跃专家集增大或 K 提高，掩盖窗口是否仍足够未被系统性压力测试覆盖。
- **预路由误差的长期效应未知**：预测即路由意味着路由错误的代价直接进入生成分布，论文用恢复 LoRA 与 on-policy 蒸馏缓解，但未给出路由准确率随序列长度、领域漂移的退化曲线。
- **prefill 与 decode 的非对称性**：whole-layer 路径针对 prefill 设计，长上下文 prefill 时的 SSD 压力与延迟尾部行为未见专门分析。

## 8. 价值与总体评价

- **概念贡献**：把"内存墙的另一半"重新定义为**存储放置决策**而非单纯的压缩问题，将静态权重与动态 KV 状态明确区分，是本文最具迁移价值的视角。
- **工程贡献**：预路由头（提前一 token、预测即路由）、四种执行路径的统一数学契约（相对 L2 < 1%，实测 ≈0.24%）、sticky-slot 的 `incr stack` 原地更新、未合并 LoRA 的服务形式，构成一套自洽且可落地的系统方案。
- **实证贡献**：在消费级 16–24 GB 机器上把 35B 级 MoE 从"装不下"变为"可服务"，并给出可后验调节的 K 旋钮；对测量噪声的诚实处理提升了结论可信度。
- **定位**：论文更像"系统可行性证明 + 机制隔离实验"，而非全面的 SOTA 竞赛。其最强的证据在吞吐与内存机制层面，最弱的证据在跨平台与跨基线的质量泛化层面。
- **适用边界**：最契合统一内存、SSD 带宽充足、权重静态且 MoE 稀疏度高的本地推理场景；对高并发、显存独立或对路由准确性极敏感的负载，收益与风险均需重新评估。
