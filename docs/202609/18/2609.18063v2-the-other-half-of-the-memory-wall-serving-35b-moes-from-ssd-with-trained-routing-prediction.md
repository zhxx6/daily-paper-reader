## 摘要
在消费级硬件上进行专家混合（MoE）推理受限于权重内存：一个35B级模型在4比特下为19.5GB，而稀疏性减少的是每个token的计算量，而非必须驻留的字节数。单纯卸载到SSD本身无济于事，因为第N+1层的专家必须在第N层输出产生之前选定，因此读取无法足够早地开始以隐藏在计算之后。我们提出Edge0，一种流式MoE推理引擎，它通过预路由器弥合这一差距：每层一个预测头提前一个token预测下一层的路由，且该预测被直接作为路由本身来使用，因此暂存的专家集合等于路由到的专家集合，不会有任何专家被丢弃。一个在学生学习路径上训练的未合并恢复LoRA，补偿了因int4量化和路由替换而损失的质量。在单台24GB机器上，Edge0在3GiB峰值活跃内存内以20tok/s服务一个35B MoE，在五个公开基准上平均与其fp16教师模型相差几个百分点。8B层级在同一框架上运行，且该框架、检查点和适配器均已开源。

## Abstract
Mixture-of-experts (MoE) inference on consumer hardware is bounded by weight memory: a 35B-class model is 19.5GB at 4-bit, and sparsity shrinks the compute per token, not the bytes that must be held. Naive offloading to SSD does not help on its own, because layer N+1's experts must be chosen before layer N's output exists, so the reads cannot start early enough to hide behind compute. We present Edge0, a streaming MoE inference engine that closes the gap with a prerouter: a per-layer head predicts the next layer's routing one token ahead, and the prediction is consumed as the routing itself, so the staged expert set equals the routed set and nothing is dropped. An unmerged recovery LoRA, trained on the student path, pays back the quality lost to int4 quantization and routing replacement. On a single 24GB machine, Edge0 serves a 35B MoE at 20tok/s inside 3GiB of peak active memory, within a few points of its fp16 teacher on average across five public benchmarks. An 8B tier runs on the same framework, and the framework, checkpoints, and adapters are open source.

# 《内存墙的另一半：用训练好的路由预测从 SSD 服务 35B MoE》论文总结

## 1. 核心问题与整体含义

- **研究背景**：1995 年 Wulf 与 McKee 提出的"内存墙"在 AI 推理时代重现。解码阶段每读取一字节权重只做几个 FLOP，硬件脊点却高出数个数量级，瓶颈是字节而非算力，而字节驻留在内存中。
- **核心矛盾**：内存中两类数据行为不同——动态状态（KV cache）随生成增长，静态权重（训练结束即固定）。工业界集中攻击动态的一半（MLA 压缩 KV、稀疏注意力、线性状态模型），而权重那一半（数十 GB）的应对方式是"放进数据中心"（专家并行、分片服务）。
- **消费级硬件的困境**：35B 级 MoE 在 4-bit 下仍需 19.5 GB，稀疏性只减少每 token 的**计算量**（约激活 3B 参数），不减少必须**存储**的字节。两种本地方案均失效：
  - 量化在 4-bit 触底，更低比特误差剧增且无后处理可恢复；
  - MoE 稀疏不改变存储需求，19.5 GB 在 24 GB 桌面上会挤占 OS 与 KV cache。
- **朴素 SSD 卸载无效的原因**：第 N+1 层的专家必须在第 N 层输出产生之前选定，读取无法足够早地启动以隐藏在计算之后，导致每个 token 每层都因磁盘延迟而停顿。
- **论文含义**：权重应作为"存储放置决策"处理——把专家权重留在 SSD 上按需流式读取，用**可训练的路由预测**打破层间依赖，从而在消费级单机上服务 35B 级 MoE。

## 2. 方法论

### 2.1 核心思想
- Edge0 是一个流式 MoE 推理引擎，由三部分构成：**SSD 流式专家层**、**预路由器（prediction is the routing）**、**未合并恢复 LoRA**。
- 关键洞察：预路由器的预测**直接作为路由本身**使用，使暂存（staged）专家集合与路由集合按构造相等，不丢弃任何专家，把近似代价从推理期转移到训练期一次性支付。

### 2.2 SSD 流式专家层（§3.1）
- mmap 量化专家 safetensors，按需读取字节范围；OS 页缓存承载热数据，峰值内存跟踪**活跃集**而非参数总量。
- 40 层 × 256 专家 MoE 每层 453 MB int4 专家权重（每专家 1.77 MB），共约 18 GB，占 24 GB 机器 RAM 的四分之三。
- 四条执行路径，从正确性基线到 prefill 批量路径：
  1. **exact**：去重按需 bundle 构建、堆叠、量化 gather，作为正确性基线；
  2. **staged**：固定槽双缓冲，解码主力；路由索引经槽表用 `take` 映射，索引不离开 GPU；重复专家集复用图节点；**incr stack** 粘性槽张量原地更新，仅重写变化的专家（避免每步重建 40 层的 9 个堆叠张量）；
  3. **hot**：每层 LRU 常驻热专家，命中走堆叠 gather，未命中回落 exact；
  4. **whole-layer**：prefill 时整层专家一次性加载（因 checkpoint 按层堆叠，只需 9 次直接读取），CPU 加载与上一层 GPU 执行重叠。
- **数学契约**：所有路径计算 `down(silu(gate(x))·up(x))`，同一量化 gather 核，测试套件逐元素对比反量化参考（相对 L2 < 1%，实测残差约 0.24%），使执行器可按层、按阶段自由切换路径而不改变输出。

### 2.3 预路由器：预测即路由（§3.2）
- **动机**：专家选择依赖尚不存在的上一层输出。预路由器用"双重移位"打破依赖——第 N 层拥有的头在 token t 上，基于第 N 层 post-attention norm 输出，预测第 N+1 层在 token t+1 的路由，使 SSD 读取与当前前向重叠。
- **提前量必须是整 token 而非一层**：类 Pre-gated MoE 的层内提前方案需要每层同步与头评估，会排空 GPU 流水线（实测每步 30–100 ms，超过其能隐藏的加载时间），且下一层注意力尚未计算。整 token 提前使头评估脱离每层关键路径，每步一次 flush 即可预测所有 staged 层（35B 为 32 层，8B 为 16 层）。
- **头结构**：每层 `fc1 → erf-gelu → fc2`，外加线性残差路径 ℓ（训练脚本从下一层 router 权重热启动，默认置零），使训练从"直接把下一层 router 应用于本层隐藏态"开始，MLP 学习修正量。
  - 输入特征 = 隐藏态 ⊕ 两个 top-k one-hot（本层本 token 实际路由到的专家、上一 token 的专家），维度 = d_model + 2E；35B 为 2048 + 2×256 = 2560，隐藏宽度 512；头为 fp16。
  - 35B 携带 33 个头（owner 6–38），8B 携带 16 个（owner 7–22）；35B 在 7–38 层消费预测，即 40 层中 32 层流式；8B 为 24 层中 16 层。
- **预测即路由**：解码时 MoE 层用预路由器 logits 路由而非原 router，走同一套 softmax-topk 或 sigmoid-group 数学（附录 A）。
- **特征漂移**：训练时头输入是本层实际执行的路由（base router 选择），解码时是头自己的预测。头不为此重训，恢复 LoRA 在部署输入分布上训练，质量测量将漂移与 int4、路由近似一并计价。
- **两种消费配置**：8B 档 K=8、每层 8 个 staged 槽；35B 档 K=4、增量粘性槽堆叠。prefill 两档均走 whole-layer 路径。

### 2.4 未合并恢复 LoRA（§3.3）
- 服务模型 = (int4 base) + (路由替换) + (LoRA)，LoRA 用于补偿前两者。
- 训练于学生路径（预路由路由激活），以交叉熵对齐教师数据，联合补偿量化与路由近似。
- **部署保持未合并**：`y = W4bit(x) + αr BAx` 作为并行 delta 计算，4-bit base 字节不动。
- **合并失败是算术问题**：LoRA delta（RMS 10⁻³）低于 4-bit group 步长，反量化后合并再量化会擦除大部分权重级 delta（注意力投影仅 34% 存活，密集投影 2%，logits 级 18% 存活）。
- 未合并路径仅占 42 MB 适配器权重，解码时间无可测增加，且严格更忠实；适配器作为文件随 checkpoint 发布，一个只读 base 服务多代适配器，换档只需换两个文件。

### 2.5 训练三阶段（§4）
- 全部在 4-bit 部署 checkpoint 的**反量化 bf16 重建**上进行（训练所服务之物），base 全程冻结。
- **Phase 1：蒸馏头**。仅训练预路由器头，损失模仿下一层真实 router，使头学会预测路由而非拟合文本。
- **Phase 2：学生路径 SFT**。LoRA 附于 attention、linear-attention、共享专家投影，**不附于 routed experts**（其权重流式且须可替换）；完整前向带预路由路由，约 **200 万行**教师生成文本。该阶段使近似可用：仅蒸馏的学生路由 checkpoint 产生重复、崩塌文本，加上 SFT 后同速同内存下输出连贯。顺序不可交换：先头后 SFT，最后 on-policy。
- **Phase 3：on-policy 蒸馏**。Phase-2 checkpoint 生成，原始 fp16 base 作为教师打分，梯度经服务路径回传；目标为 **reverse KL**（模式寻求），作用于教师 top-k token，top-k 外的质量由 tail 项承载而非丢弃；语料约 **20 万行**，为 SFT 的十分之一。
- **迭代经济**：换路由宽度只需换适配器文件。正因如此 35B 发布 K=4 而非 base 的 K=8——16 GB 机器上同会话 A/B，K=8→K=4 解码从 3.3 升至 6.4 tok/s 并降低峰值活跃内存，质量仍保持。
