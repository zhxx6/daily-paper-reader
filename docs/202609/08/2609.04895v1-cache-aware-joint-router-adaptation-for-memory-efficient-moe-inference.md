## 摘要
混合专家模型仅激活每个令牌的一小部分专家，但完整的专家集常常超出GPU内存，导致解码过程中反复的权重传输。我们将专家缓存管理视为一个模型侧的算法问题，并提出一个缓存感知的训练后框架，它联合调整MoE主干和轻量级辅助缓存路由器，同时在推理时保留原生的Top-K专家选择规则。其仅更新模式，即时间路由器，预测同层复用并为未来令牌保留专家，无需主动加载。完整时空路由器增加了一个空间路由器，它利用因果前驱的隐藏状态在目标层访问前细化缓存。我们在Qwen3和GPT-OSS上评估了这两种模式，涉及GSM8K、MATH和CommonsenseQA数据集。时间路由器在匹配的语言模型基线上持续提高了缓存命中率并减少了专家权重流量。在Qwen3上，时空路由器在三个任务中实现了最佳的负载调整效率，调整后命中率提高了1.15至18.03个百分点，与最强评估预取基线相比，流量减少了4.6%至53.3%；在GPT-OSS上的结果具有竞争力但依赖于任务。仅辅助消融保持了基线准确性，但带来的缓存收益有限，而联合训练后产生了更大的改进。敏感性分析表明，缓存容量控制传输需求，而细化预算是预访问覆盖与主动流量之间的权衡因素。

## Abstract
Mixture-of-Experts (MoE) models activate only a small subset of experts per token, but the full expert set often exceeds GPU memory, causing repeated weight transfers during decoding. We formulate expert-cache management as a model-side algorithmic problem and propose a cache-aware post-training framework that jointly adapts the MoE backbone and lightweight auxiliary cache routers while preserving the native Top-K expert-selection rule at inference. Its update-only mode, Temporal Router, predicts same-layer reuse and retains experts for future tokens without proactive loading. The full Spatio-Temporal Router adds a Spatio Router that uses the causal predecessor's hidden state to refine the temporal cache before target-layer access. We evaluate both modes on Qwen3 and GPT-OSS across GSM8K, MATH, and CommonsenseQA. Temporal Router consistently improves cache hit rate and reduces expert-weight traffic over matched LM-only baselines. On Qwen3, Spatio-Temporal Router achieves the best load-adjusted efficiency across three tasks, improving adjusted hit rate by 1.15--18.03 points and reducing traffic by 4.6--53.3% relative to the strongest evaluated prefetching baseline; results on GPT-OSS are competitive but task-dependent. An auxiliary-only ablation preserves baseline accuracy but yields modest cache gains, whereas joint post-training produces larger improvements. Sensitivity analyses show that cache capacity controls transfer demand, while the refinement budget governs the trade-off between pre-access coverage and proactive traffic.

## 1. 论文的核心问题与整体含义（研究动机和背景）

Mixture-of-Experts（MoE）架构通过为每个 token 仅激活少量专家来改善 Transformer 模型容量与计算效率之间的权衡。然而，整个专家集合的权重可能远超单个 GPU 的内存容量，即便计算上稀疏，随着推理阶段解码的推进，仍然存在专家权重反复从 CPU/宿主机或外部存储搬运到 GPU 的过程，导致显著的内存带宽开销与解码时延。

已有工作（如 MoE-Infinity、ProMoE、FineMoE、LRU/LFU/LRFU、SpecMD、Temporally Extended MoE 等）从启发式缓存策略、专家权重预取、系统级调度等角度尝试解决此问题，但这些方法要么无法直接优化驻留专家在未来解码步骤中的效用，要么将缓存问题单纯视为运行时预测与调度问题，没有从模型侧算法层面进行联合优化。

论文将“专家缓存管理”重新定义为一个模型侧算法问题，提出一种缓存感知的后训练框架，在保持推理阶段原生 Top-K 路由规则不变的前提下，联合适配 MoE 主干网络与轻量级辅助缓存路由器，旨在提升缓存命中率、减少解码阶段专家权重的传输量，同时可控地维持任务精度。

## 2. 论文提出的方法论

### 核心思想

方法的核心是透过训练后的“缓存路由”机制来管理 GPU 上有限的专家驻留空间。整个缓存生命周期有两个干预时机：

1. **访问后保留（post-access cache retention）**——在目标 MoE 层执行后，确定保留哪些专家供同一层未来 token 使用。
2. **访问前精化（pre-access cache refinement）**——在目标 MoE 层计算前，利用因果上文中可用的信息调整驻留专家，使得更多将要被原生 Top-K 路由选中的专家已在缓存中。

### 两种部署模式

- **Temporal Router（时间路由器，更新-唯模式）**：
  - 利用当前层当前 token 的隐藏状态预测同层下一个 token 的专家需求和分布（pT）。
  - 结合原生路由器输出（pR）构造保留优先级向量。
  - 推理时仅在 MoE 层访问后执行缓存更新（保留、按需加载缺失专家、必要时驱逐），**不做任何主动预取**，故 P=0。
  - 优化目标：在训练时通过缓存覆盖损失，预测下一步同层原生路由器的分布。
  
  更新函数 `UpdateCache` 的要点是：将当前访问实际缺失且被按需加载的选中专家加入缓存；若空间不足，则从非当前选中的驻留专家中优先驱逐缓存优先级最低的一个。

- **Spatio-Temporal Router（时空路由器，完整模式）**：
  - 在 Temporal Router 的基础上增加一个 Spatio Router：
    - 将上一个“因果位置”（可能是 token t-1 的最后一层，或当前 token 的上一层）的隐藏状态输入 Spatio Router，预测下一个 MoE 位置的专家需求分布。
  - 完整的缓存优先级由三个分布相加而成：
    - `s_ST = (pR_{t-1,l} + pT_{t-1,l}) + pS_{ρ(t,l)}`。
  - 在目标层访问**前**先对缓存做有界精化：在推理中取细化的优先级向量中 Top-R 个候选（R 为精化候选预算），若其优先级高于缓存中优先级最低的驻留专家且该专家不在缓存中，才实施一次主动加载（proactive load）。
  - 精化后，又使用共享的 Temporal Router 更新逻辑，为下一个解码步骤构造新的临时缓存。

### 损失函数设计

- 使用带温度的软掩码对硬 Top-B 集合成员资格做代理（soft surrogate membership）。
- 定义缓存覆盖损失 ℓ_cache(s,q) = Σ_e q_e [1 − m_e(s)]，其中 q 为目标专家分布。
- Temporal Router 的损失目标是下一位置的持有者路由分布；Spatio-Temporal Router 的损失目标是当前访问的持有者路由分布。
- 总损失为语言建模损失加上加权的 cache 损失：
  - `L = L_LM + λ_T L_T`（Temporal 模式）
  - `L = L_LM + λ_ST L_ST`（时空模式）

### 值得注意点

作者强调，主网络中“原生路由器”的参数是可训练并可持续参与联合优化的——所谓“保持原生 Top-K 规则”只保留下采样/选择规则不变，不冻结 native router 本身的输出分布。缓存路由器输出只决定放哪些专家进缓存，**真正执行计算的专家仍然由原生 Top-K 决定**；所有推理时预测均基于因果可用的状态，训练时的目标分布只在教师强制下提供监督信号。

## 6. 主要结论与发现

1. **Temporal Router（仅更新模式）一致优于经典启发式策略**，在 Qwen3 上相较于最好的传统命中率基线，命中率提高 10.46–33.34 个百分点（不同数据集不等），同一时间 Load 显著下降（如 GSM8K：1353 → 974 MB/token）。
2. **在 Qwen3 上时空路由器在总体负载调整效率上均取得最好结果**：
   - 调整命中率相对 ProMoE 提升 1.15–18.03 个百分点；
   - 流量相对 ProMoE 减少 4.6%–53.3%。
   - GPT-OSS 上看结果与任务相关（CommonsenseQA 第一、MATH 第二、GSM8K 表现较低但准确率最高）。
3. **两种模式属于不同工作点**：Temporal Router 面向最低流量（零主动加载），时空路由器用有界主动加载换取更高预先访问覆盖与更早专家可用性。
4. **联合后训练效果远优于 auxiliary-only 训练**。Auxiliary-only 几乎不损失精度但只得到少量缓存改进，而联合训练可大幅提升命中与流量指标，并产生可调整的准确率权衡。
5. **仅做 Spatio 精化而不做时间保留**可达到较高的 raw hit，但由于所有替换都发生在预取阶段，会导致负载调整命中和总流量更差。
6. **缓存容量 B 控制传递需求**；而精化候选预算 R 在给定容量下控制“预访问覆盖 ↔ 主动流量”的权衡。
7. **缓存损失权重 λ 控制质量-流量权衡**。更高权重能提升本地化并大幅降低负载，但过高会导致专家使用高度集中，并对任务准确率产生明显不利影响。
8. 完美的 raw hit rate 不应作为高效缓存的证明（Temporally-Extended MoE 100% hit 但 load-adjusted 指标与准确率低）。

## 7. 优点

- **问题切得新颖且清晰**：不做端到端系统，而从模型侧“后训练缓存路由适配”角度切入，使该问题不与闭环运行时耦合、可在模型层算法层面直接优化。
- **保留原生 Top-K 语义，不改变模型推理规则**，用辅助路由器只决定“谁在缓存里”，并由原生路由器决定实际执行的专家，这是既简洁又实用可落地的设计。
- **框架统一且模块化**：Temporal Router 可以单独作为更新-唯策略部署；加一层 Spatio Router 即可扩展为完整预取策略。两种模式共享 update 函数，训练部署方案清晰，候选预算 R 可在推理时调整而不需重新训练。
- **度量设计较为严谨**：以 Load per token 为主要成本指标，并提出 Adjust Hit 来惩罚主动预取开销，避免只凭 raw hit rate 衡量效果的误导性结论。
- **消融分析深入而系统**：覆盖“适配范围、路由器构成、容量与预算、cache 损失强度、路由集中强度”等层面，为实际部署参数选择和权衡给出了充分依据。
- **权衡分析与监控指标丰富**：除性能与流量的粗略对比外，还观察了 cache 损失权重对路由熵、有效专家数和 Top-8 集中度的效应，说明作者并未回避该方法改变路由分布可能带来的副作用。

## 8. 不足与局限

- **不是端到端服务栈实验**：论文测量的是模拟的负载/传输量指标，真实时延与吞吐仍取决于显式调度、重叠计算流水线、带宽及批处理策略；prefill 被排除统计但 prefill 决定了初始缓存，导致报告指标偏向解码阶段效率而非请求级端到端增益。
- **未给出资源/算力核算**：未报告 GPU 类型、运行时长和总 GPU 时数；以论文的“多配置分开训练再统一评估”实验模式而言，隐含的计算消耗其实较高。
- **比较公平性受限**：主实验比较的是“完整推理配置”，而所提方法可以适配重排路由分布，因此与基线不共享同一路由轨迹；公平性更偏向“可替代的高层配置比较”，而非严格同轨策略对比。
- **baseline 来源各异且评价口径不统一**：ProMoE、SpecMD、Temporally-Extended MoE 等原方法各自的任务定义与系统假设不同；在本论文的单一缓存设置下做了统一化复现，但相对优势可能在不同存储层级或运行时策略下改变。
- **模型覆盖有限**：实验只在两个开源 MoE 上开展，未覆盖更大规模或混合架构模型；cache 容量分析与部分消融只在 Qwen3/GSM8K 一个任务上展开，结论的外推能力受限。
- **准确性权衡并非没有成本**：所提出的训练使缓存更有效时，路由会更集中、模型任务精度可能下降；在分布式专家并行场景下，集中还可能导致负载不均衡，而论文没有对此做量化分析或缓解。
- **Auxiliary-only 对照组不能完整区分“原生路由器改变”和“其他骨干改动”的贡献**，结果只能证明联合调优整体有效，无法断言单个参数子集的确切贡献程度。
