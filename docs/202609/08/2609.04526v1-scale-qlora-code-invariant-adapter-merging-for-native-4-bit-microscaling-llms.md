## 摘要
将LoRA适配器合并到其基础模型中是标准的部署实践：它移除了运行时适配器的每前向开销，并留下一个任何服务堆栈都可以加载的独立检查点。在原生4位微缩放检查点（NVFP4，MXFP4）上，该步骤不再是免费的。合并后的权重必须通过量化器写回，这会重新派生检查点的离散E2M1码平面（约占工件字节的90%），因此部署工件与一种量化约定耦合，并且其生命周期中后续每次触及码的事件都可能移动它。若天真地执行，该步骤比脆弱更糟：它会删除适配效果，最多降低39个百分点，因为面对已在网格上的基础模型，重建最优解就是该基础模型。Scale-QLoRA则不同：它仅适配原生每块缩放字段，在部署网格上训练这些缩放，并冻结每个E2M1码。在固定的原生格式、缩放网格、块布局和码平面内，合并随后是逐位精确的恒等操作，且合并工件是码不变的。在四个模型和四个任务上，Scale-QLoRA和考虑合并的QAT-LoRA都是无损的，因此我们声称两者之间没有准确率排序；它们在结构上有所不同，即QAT-LoRA通过量化器重新派生码平面，而Scale-QLoRA精确保留该平面。这种差异正是生命周期代价所在：最近舍入实现之间在测量任务上可能相差约一个百分点，而更极端的规则不匹配可能导致权重空间工件降至约0%，我们将其报告为敏感性界限而非部署频率。保留码平面还从训练中移除了权重空间直通估计器（稠密8B模型上每步3.9倍），并支持精确回滚、码平面去重以及约125倍更快的仅缩放任务交换。

## Abstract
Merging a LoRA adapter into its base model is standard deployment practice: it removes the runtime adapter's per-forward overhead and leaves a single standalone checkpoint any serving stack can load. On a native 4-bit microscaling checkpoint (NVFP4, MXFP4) that step stops being free. The merged weights must be written back through a quantizer, which re-derives the checkpoint's discrete E2M1 code plane (roughly 90% of the artifact's bytes), so the deployed artifact becomes coupled to one quantization convention, and every later code-touching event in its lifecycle can move it. Done naively the step is worse than fragile: it deletes the adaptation, by up to 39 pp, because against an already-on-grid base the reconstruction optimum is that base. Scale-QLoRA instead adapts only the native per-block scale field, trains those scales on the deployment grid, and freezes every E2M1 code. Within a fixed native format, scale grid, block layout and code plane, merging is then a bit-exact identity and the merged artifact is code-invariant. Across four models and four tasks, Scale-QLoRA and merge-aware QAT-LoRA are both accuracy-lossless, so we claim no accuracy ordering between them; they differ structurally, in that QAT-LoRA re-derives the code plane through a quantizer while Scale-QLoRA preserves it exactly. That difference is what the lifecycle prices: nearest-rounding implementations disagree by about a point on the measured task, and more extreme rule mismatches can drive the weight-space artifact to ~0%, which we report as a sensitivity bound rather than a deployment frequency. Preserving the code plane also drops the weight-space straight-through estimator from training (3.9x per step on the dense 8B model) and enables exact rollback, code-plane deduplication, and a ~125x faster scale-only task swap.

## 核心问题与整体含义

- **研究动机**：将 LoRA 适配器合并（merge）回基础模型是标准部署实践，可以消除运行时适配器的每前向开销，并生成单个独立检查点。但在原生 4 位微缩放格式（如 NVFP4、MXFP4）的检查点上，这一操作并不简单：合并后的权重必须通过量化器写回，从而重新派生离散 E2M1 码平面——约占工件总字节的 90%。
- **核心问题**：传统"反量化→加 LoRA delta→再量化"的朴素合并会严重删除适配效果，在 NVFP4 Llama-8B 的 Banking77 任务上最高损失 37–39 个百分点。其根本原因是：当基础权重已精确位于可表示的量化网格上时，针对重建误差的量化器，其最优解就是未适配的基础模型本身，而非适配后的模型。此外，合并后的工件与训练时所用的特定量化规则耦合，在后续生命周期事件（导出、格式转换、引擎升级、重量化）中一旦遇到不同舍入规则，就可能被破坏。
- **核心洞察**：文章提出，合并策略的关键区别不在于合并时的准确率损失（两个考虑合并的无损方法都无损），而在于合并后留下的工件结构：是否保留码平面不变。
- **提出的方法**：Scale-QLoRA 只适配每个块的缩放（scale）因子，冻结所有 E2M1 码，在训练期间使用量化感知缩放训练（QAST）将有效缩放放到目标网格上。这样，在固定的原生格式、缩放网格、块布局和码平面下，合并是逐位精确的恒等操作，工件是"码不变"（code-invariant）的，与任何量化约定无关。

## 方法论：核心思想与技术细节

### 核心思想

Scale-QLoRA 的出发点是用低秩修正作用于**每块的缩放字段**而非权重量：通过参数量约等于普通 LoRA 的低秩矩阵，直接纠正量化权重中缩放因子的取值，同时保证 E2M1 码在训练和合并过程中完全不发生改变。

### 关键技术细节

- **模型结构**：每个权重表示为 `W[o,i] = c[o,i] · eff_scale[o, g(i)]`，其中 c 是 E2M1 码（值域为 ±{0, 0.5, 1, 1.5, 2, 3, 4, 6}），eff_scale 是共享的块级缩放。NVFP4 使用块大小 16，缩放存为 E4M3 字节 × fp32 每张量标量；MXFP4 使用块大小 32，缩放为 E8M0 的无尾数指数字节。
- **前向公式**：学习低秩修正 `∆S = (BA)(α/r)`，其中 B 为 [out, r]，A 为 [r, G]，G 为每行的分块数。公式为：
  - `eff_scale′ = eff_scale + ∆S`（逐块）
  - `W′[o,i] = c[o,i] · eff_scale′[o, g(i)]`
  A 是块级矩阵而非全宽矩阵，因此在相同秩下参数比权重空间 LoRA 少约 1.8 倍。
- **QAST 训练（核心机制）**：由于缩放需要写入离散网格（E4M3 或 E8M0），连续值不可直接写回，Scale-QLoRA 必须在训练中就把缩放舍入到正确网格。QAST 的实现为：
  - `eff_q = round_grid(eff_scale′)`
  - `eff_ste = eff_scale′ + (eff_q − eff_scale′).detach()`
  即前向使用在网格上的值，反向梯度通过直通估计器流向低秩因子，从而保证训练时模型看到的就是部署时能写出的缩放值，合并时只需直接写入该字节，无需再次量化——码平面为原始不变。
- **MoE 适用性**：针对数百个专家的超大 MoE（如 gpt-oss-120B 和 DeepSeek-V4-Flash），用批处理分组专家内核将全部专家的权重更新合并为单次 bmm，避免逐专家 Python 循环构建过于巨大的 autograd 图。训练通过 DeepSpeed 专家并行进行。
- **稳定性配方**：
  - 对 E4M3 的 min(eff, 448·ws2) 上限钳制：防止 MoE 训练因钳位以上梯度泄漏而数值不稳定（Qwen-30B 上不加钳制在第 18 步出现非有限值，加钳制则正常）。
  - 验证集早停法：提供鲁棒的单学习率策略——低学习率无法在弱基础任务上学到足够效果，高学习率又会在强基础任务上崩溃；早停模式统一处理两种情形，无崩溃。
  - 合并阶段必须复用 QAST 前向的同一网格与钳制路径，否则会产生人工合并损失。
- **和其他方法的关系**：
  - QAT-LoRA（合并感知权重空间基线）：在完整权重上用 STE 伪量化训练，合并时可复现训练，但必须量化整个权重，误差约 3×10⁻³，且合并产物依赖训练量化规则与后续部署规则的一致。
  - 朴素 QLoRA 合并：在量化网格上用无 STE 的训练，合并时再量化，会导致解码差异。
  - PEQA（尺度空间基线）：逐通道缩放但码冻结，可理解为尺度空间但不足以在低秩语境下闭合表现差距。

## 主要结论与发现

1. **合并无损但结构不同**：
   - Scale-QLoRA 与 QAT-LoRA 在所有主要表项目上均达到准确率无损，合并方差最多 0.2 pp，区间为 ±0.5–1 pp。
   - Scale-QLoRA 在权重空间中逐位精确：max|∆W| = 0，E2M1 码逐字复制；QAT-LoRA 在权重空间并非逐位精确（max|∆W| ≈ 3×10⁻³），仅靠经验实现准确率无损。
2. **码不变性的五个收益**：
   - 受部署量化规则族保护（在 vLLM 栈上对 5 种规则扫描：Scale-QLoRA 跨数据集持平 0.0 pp，QAT-LoRA 摆动 91.6–97.6 pp）。
   - 跨任务共享码平面：Llama 上 0/224 个码字节差异，存储共享 3.0×（M=4）。
   - 精确回滚：对合并时实际应用的网格采样 delta 进行字节级减法即可恢复基座，无需保留第二份完整基座。
   - 存储去重与补丁稀疏：压缩补丁小 21.1 倍，分块级别去重更小 9.0 倍。
   - 基于码字节的不变量进行可审计跟踪。
3. **朴素合并为何崩溃**：在已网格对齐的基座上，合并权重重建误差的最优解就是基座本身；重构较慢的量化规则反而能保留适配，重构更优的规则删除更多（在 NVFP4 和 E8M0 上均观察到该方向性关系）。原文用"重构图最小化是合并时的错误目标"与数据呼应（如 DeepSeek 上权重 MSE 搜索破坏 105–110% 的适应增益）。
4. **效率提升**：训练每步便宜 3.9 倍（稠密）/2.2 倍（MoE），因 QAST 只量化缩放张量而非完整权重；合并时切换任务约快 125 倍（仅写 ~1/16 的字节），且不引入额外前向开销。
5. **表示角度**：PEQA ⊂ 每块+冻结码 ⊂ 权重空间；Scale-QLoRA 是中间项的参数化，未观察到该方法在预测精度上的有害瓶颈。
