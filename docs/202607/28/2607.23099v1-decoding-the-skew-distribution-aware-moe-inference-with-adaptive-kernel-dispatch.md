## 摘要
混合专家（MoE）推理由稀疏专家GEMM组成，其形状随运行时路由分布而变化。现有的服务系统通常使用静态令牌计数桶来选择融合MoE内核，忽略了每个专家的路由分布，该分布决定了图块填充、内存重用和内核效率。我们引入了一个分布感知框架，用于建模和基准测试MoE推理。该框架将紧凑的有效专家度量与基于狄利克雷的逆向建模过程相结合，生成可控的路由分布，用于系统的硬件研究。通过该框架，我们展示了最佳的融合MoE内核随路由偏斜和令牌计数而变化。我们进一步提出了DA-MoE，一个面向NVIDIA GPU的驻留GPU内核调度运行时，它将实时路由直方图与离线调优分布进行匹配，并选择接近最优的融合MoE内核，无需CPU-GPU同步。在HumanEval-X服务轨迹上，DA-MoE在DeepSeek-V3上将融合MoE延迟的几何平均值提升了1.16倍，在Kimi K2上提升了1.29倍，峰值加速分别为1.40倍和1.56倍。

## Abstract
Mixture-of-Experts (MoE) inference consists of sparse expert GEMMs whose shapes vary with the runtime routing distribution. Existing serving systems typically select fused-MoE kernels using static token-count buckets, ignoring the per-expert routing distribution that determines tile padding, memory reuse, and kernel efficiency. We introduce a distribution-aware framework for modeling and benchmarking MoE inference. The framework combines the compact Effective Experts metric with a Dirichlet-based reverse-modeling procedure that generates controllable routing distributions for systematic hardware studies. Using it, we show that the best fused-MoE kernel changes with routing skew and token count. We further present DA-MoE, a GPU-resident kernel-dispatch runtime for NVIDIA GPUs that matches the live routing histogram to offline-tuned distributions and selects a near-optimal fused-MoE kernel without CPU--GPU synchronization. On HumanEval-X serving traces, DA-MoE improves geomean fused-MoE latency by 1.16X on DeepSeek-V3 and 1.29X on Kimi K2, with peak speedups of 1.40X and 1.56X.

## 2. 方法论：核心思想、关键技术细节、公式或算法流程

### 核心思想
- 引入**有效专家（Effective Experts, eff_exp）** 度量，量化路由集中程度；利用**Dirichlet分布**逆向建模生成可控路由分布，用于离线分析和在线匹配；构建**DA-MoE运行时**，根据实时路由直方图，通过离线调优的示例表在GPU上直接选择近最优内核，无需CPU干预。

### 关键技术细节

#### (a) 路由偏斜建模
- **effective experts** 定义为 \( \text{eff\_exp} = \frac{(\sum t_i)^2}{\sum t_i^2} \)，\( t_i \) 为专家 i 接收的token数。范围 [1, N]，值越小表示路由越集中。
- **Dirichlet逆向建模**：使用对称Dirichlet分布 Dir(α)，其中 α 为标量浓度参数。eff_exp 随 α 单调递增。通过二分搜索（Algorithm 1）从目标 eff_exp* 反求 α，生成合成路由分布，记为 ddist:X，其中 X 为偏斜倍数（eff_exp* = N/X）。

#### (b) 离线自动调优
- 对每个token计数桶（32,64,128,256,512），用 ddist:X 生成一组示例分布（X取值1.1~4.0）。
- 将所有可用融合MoE内核在这些分布上基准测试，记录每个示例对应的最低延迟内核ID。
- 每个示例表示为排序后、L2归一化的每专家token计数向量，构成映射表并上传到GPU。

#### (c) 在线调度（DA-MoE运行时）
- 每个MoE层：路由网络输出后，统计每专家token直方图，排序并L2归一化，与当前桶的示例表进行余弦相似度匹配，得到内核ID。
- 利用**条件CUDA图（conditional CUDA Graphs）**，在GPU内部完成直方图构建、排序、匹配和分支选择，随后直接启动对应融合MoE内核，整个流程在一个CUDA图内执行，完全避免CPU-GPU同步。

### 算法流程（文字描述）
1. **离线阶段**：对每个token计数桶，用Dirichlet采样生成多个偏斜等级的路由分布→基准测试所有内核→构建(示例向量, 最佳内核ID)的查找表→上传至GPU。
2. **在线阶段**：MoE层前向时→路由logits→构建每专家token计数直方图→降序排序+L2归一化→余弦相似度匹配最优内核→通过条件CUDA图启动内核。
