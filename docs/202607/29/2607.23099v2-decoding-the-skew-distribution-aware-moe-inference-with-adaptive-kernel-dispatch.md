## 摘要
混合专家（MoE）推理由稀疏专家GEMM组成，其形状随运行时路由分布变化。现有服务系统通常使用静态token计数桶选择融合MoE内核，忽略了决定tile填充、内存复用和内核效率的逐专家路由分布。我们引入了一个分布感知框架，用于建模和基准测试MoE推理。该框架将紧凑的有效专家度量与基于狄利克雷的逆向建模过程相结合，可生成可控的路由分布以进行系统性硬件研究。利用该框架，我们展示了最佳融合MoE内核随路由偏斜和token数量变化。我们进一步提出了DA-MoE，一种适用于NVIDIA GPU的驻留GPU内核调度运行时，它能够将实时路由直方图与离线调优分布进行匹配，并在无需CPU-GPU同步的情况下选择接近最优的融合MoE内核。在HumanEval-X服务轨迹上，DA-MoE在DeepSeek-V3上将融合MoE几何平均延迟提升1.16倍，在Kimi K2上提升1.29倍，峰值加速比分别达到1.40倍和1.56倍。

## Abstract
Mixture-of-Experts (MoE) inference consists of sparse expert GEMMs whose shapes vary with the runtime routing distribution. Existing serving systems typically select fused-MoE kernels using static token-count buckets, ignoring the per-expert routing distribution that determines tile padding, memory reuse, and kernel efficiency. We introduce a distribution-aware framework for modeling and benchmarking MoE inference. The framework combines the compact Effective Experts metric with a Dirichlet-based reverse-modeling procedure that generates controllable routing distributions for systematic hardware studies. Using it, we show that the best fused-MoE kernel changes with routing skew and token count. We further present DA-MoE, a GPU-resident kernel-dispatch runtime for NVIDIA GPUs that matches the live routing histogram to offline-tuned distributions and selects a near-optimal fused-MoE kernel without CPU--GPU synchronization. On HumanEval-X serving traces, DA-MoE improves geomean fused-MoE latency by 1.16X on DeepSeek-V3 and 1.29X on Kimi K2, with peak speedups of 1.40X and 1.56X.

## 1. 核心问题与整体含义（研究动机和背景）

混合专家（MoE）大语言模型通过稀疏激活专家子网络来扩展模型容量而保持推理计算可控。然而，现有推理服务系统（如 TensorRT-LLM、vLLM、FlashInfer）通常采用**静态 token 计数桶**（按批量大小）来选择预编译的融合 MoE 内核（fused-MoE kernel），完全忽略了**运行时每专家的路由分布**。路由分布决定了每个专家 GEMM 的 token 数量，进而影响 MMA tile 的形状选择、填充（padding）开销、内存复用效率等微架构性能。作者指出，现有工作缺乏对路由偏斜（skew）的数学刻画与可控生成方法，且没有 GPU 驻留的低开销内核分发机制。论文旨在填补这一空白，通过分布感知的内核选择和设备端动态调度，显著提升 MoE 推理的延迟性能。

## 2. 方法论：核心思想、关键技术细节

### 2.1 路由偏斜建模
- **有效专家指标（Effective Experts, `ef f_exp`）**：  
  `ef f_exp = (∑_i t_i)^2 / ∑_i t_i^2`，其中 `t_i` 为第 i 个专家接收的 token 数。该指标直观反映路由集中程度：值接近专家总数 E 表示均匀分布，接近 1 表示极度偏斜。
- **Dirichlet 逆建模**：  
  采用对称 Dirichlet 分布 `Dir(α)` 生成可控路由分布。通过二分搜索使生成的分布具有目标 `ef f_exp*`，从而得到参数 `α`。用户通过参数 `X` （`ef f_exp* = E/X`）即可连续调节偏斜度（`X∈[1, E]`，X 越大越偏斜）。算法 1 描述了二分搜索过程。

### 2.2 离线自动调优
- 对每个 token-count 桶（32,64,128,256,512），生成一系列 synthetic 路由分布（对应不同 skew level `X`），在 B200 GPU 上对 TRTLLM 所有融合 MoE 内核变体（不同 MMA tile 形状、软件流水线深度、内存加载路径）进行基准测试，记录每个分布下的**最优内核 ID**。
- 每个分布用一个**exemplar**表示：将每专家的 token 计数向量降序排序后 L2 归一化。这样不同偏斜但相同分布形态的层可映射到同一个 exemplar。

### 2.3 在线动态调度（DA-MoE）
- **全 GPU 驻留**：在 CUDA 图（CUDA Graph）内部，路由器输出后，GPU 立即计算每专家 token 直方图 → 排序 → L2 归一化 → 与当前 token 桶下的离线 exemplar 表进行余弦相似度匹配，选出最接近 exemplar 对应的最优内核 ID。
- **利用条件 CUDA 图（Conditional CUDA Graph）**：CUDA 12.8 引入的设备端 SWITCH 节点，使得数据依赖的分支完全在 GPU 内执行，无需 CPU 介入和同步。整个选择过程（直方图构建、排序、匹配、条件分支发射）封装在单个 CUDA 图中，延迟仅约 14 μs，远小于融合 MoE 内核执行时间。

### 2.4 架构启示
- SIMT GPU 需要低开销的 GPU 驻留分支原语（如条件 CUDA 图）。
- 空间加速器（如脉动阵列）需要可重构的 tile/阵列划分，以灵活服务热专家而避免过填充冷专家。

## 6. 主要结论与发现

1. **路由偏斜存在**且与层和 token 计数强相关（DeepSeek-V3 上 `ef f_exp` 变化超过 2×）。
2. **最佳 Tile-N 和内核配置**随路由偏斜和 token 计数而变化；即使在固定 Tile-N 下，单个内核无法在所有分布上占优。
3. **DA-MoE 带来显著加速**：
   - Fused-MoE 延迟几何平均提升：DeepSeek-V3 1.16×，Kimi K2 1.29×；峰值分别 1.40× 和 1.56×。
   - 端到端延迟几何平均提升：1.15×（DeepSeek-V3），1.26×（Kimi K2）；峰值 1.37×（DeepSeek-V3）和 1.51×（Kimi K2）。
4. **接近 Oracle**：对于 token 32-256，DA-MoE 延迟仅比 Oracle 高 0.3%~3.7%；512 时因覆盖不足差距约 20%。
5. **增益随路由偏斜和专家并行度增加而增大**，印证方法价值在高偏斜、高 EP 场景更突出。
6. **开销可控**：GPU 驻留分发约 14 μs，远小于 MoE 执行时间，不影响端到端增益。
7. **Dirichlet 分布能精准建模真实路由**（余弦相似度 0.97），优于 Beta（0.92）和指数（0.94）。

## 8. 不足与局限

1. **离线调优静态化**：exemplar 表在推理前固定，无法适应实时分布漂移（如新数据集带来的未覆盖偏斜区间）。Token 512 时 oracle 差距达 20% 说明覆盖不足。

7. **未报告离线调优所需 GPU 小时数**，对部署可预测性略有欠缺。
